# 추적 매트릭스

> **채점을 방어하는 한 장.** 세부 평가 기준의 감점 사유는 결국 하나다 —
> 화면 · API · ERD 가 어긋나는 것. 이 표가 그 셋을 한 줄에 놓는다.
>
> ```
> 화면에 보이는 값  →  API 응답 필드  →  테이블 · 컬럼
> ```
>
> 재료: `docs/10-화면-필드.md` · `api/openapi.yml` · `db/schema.dbml`
> 작성일: 2026-09-09

## 읽는 법

| 표기 | 뜻 |
|---|---|
| **실시간** | 서버가 Music.app · 외부에 그때그때 물어 온다. 저장하지 않는다 |
| **계산** | 다른 값으로 만든다. 컬럼이 없는 것이 맞다 |
| **고정** | 클라이언트에 박힌 문구. API 도 DB 도 없다 |

## 화면에 없는 것 둘

| | API | 테이블 |
|---|---|---|
| 곡이 끝난 사건 | `POST /plays` | `play` |
| 요청이 어떤 자리를 위한 것인가 | `GET /turns/{id}` → `context` | `turn.context` |

**둘 다 화면에 안 보인다. 그런데 둘이 짝이다.**

`play` 는 무엇이 일어났는지를 적고(왜 끝났나 · 몇 초에 나갔나),
`turn.context` 는 그것이 **어떤 자리에서** 일어났는지를 적는다.
사건마다 자리를 복사하지 않고 `play → queue_item → turn` 으로 잇는다.

둘을 합치면 "공부할 때 무엇을 넘겼나"를 셀 수 있다. **다만 지금 읽는 코드는
곡 단위까지다** — 맥락별 집계는 표본이 쌓인 뒤다(§6 다음 단계 8번).

**화면 → API → ERD 사슬의 유일한 예외이며, 그 이유를 여기 적어 둔다.**
