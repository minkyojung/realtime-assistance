# 호스트 계약

> 터미널 안에 여러 앱을 담는 껍데기가 무엇을 갖고, 앱에게 무엇을 요구하는가.
> 작성일: 2026-09-09

---

## 0. 한 줄

```
호스트가 파는 것은 화면이 아니라 조작법이다. 화면은 앱이 그린다.
```

---

## 1. 호스트가 가진 것 — 두 줄

```
┌──────────────────────────────────────────────┐
│                                              │
│          앱 본문 — 앱이 전부 그린다            │
│                                              │
├──────────────────────────────────────────────┤
│ › 입력창                                      │  ← 호스트
├──────────────────────────────────────────────┤
│ Recently Added · 157 ▶ Perth · 3:12/4:05  $0.02│  ← 호스트
└──────────────────────────────────────────────┘
```

**입력창 한 줄, 상태줄 한 줄.** 그 위는 앱의 것이다.

그래서 앱마다 화면이 달라도 된다. 음악은 목록을 그리고, 채팅 같은 앱이
들어온다면 대화를 그리면 된다. 음악에 채널 목록을 붙일 이유가 없다.

**상태줄은 모든 앱의 상태를 모은다.** 어느 앱을 보고 있든 음악이 무엇을
재생 중인지 계속 보인다. 맥의 메뉴바와 같다.

---

## 2. 조작법 — 이것이 호스트의 유일한 자산

| | 뜻 |
|---|---|
| **입력창** | 모든 것의 입구. 앱이 바뀌어도 여기는 안 바뀐다 |
| **글자** | 의도 — "조용한 거", "누가 나 찾았어?" |
| **`/`** | **갈 곳과 할 것.** 사이드바를 대신한다 |
| **`shift+tab`** | 모드 바꾸기 — `Ask AI` ⇄ `Search` |
| **`ctrl+f`** | 곧장 검색으로 (`shift+tab` 과 같은 자리) |
| **`ctrl+j`** | 로그 펼치기 |
| **`tab`** | 앱 안에서 다음. 되돌아가는 짝은 없다 — `/` 로 곧장 간다 |
| **`/앱이름`** | 앱 전환 |
| **`?`** | 도움말 |
| **`esc`** | 한 단계 물러나기 |
| **`ctrl+c`** | 종료 |

### 칸 배분은 호스트가 준다

터미널은 폭이 예측 불가하고 폰트 메트릭이 없다. 그래서 **"자를지 말지"를
앱이 정해야 하고, 자르는 것은 곧 우선순위 선언이다.**

모든 TUI 레이아웃은 칸마다 숫자 넷을 정하는 일로 환원된다.

| | 뜻 |
|---|---|
| `Min` | 이보다 좁아지면 이 칸은 사라진다 |
| `Weight` | 남는 공간을 가져가는 비율 |
| `Max` | 더 넓어지지 않는다. 없으면 한 칸이 다 먹고 가운데가 빈다 |
| `Drop` | 좁아질 때 희생되는 순서. 0 이면 절대 안 버린다 |

`style.Columns` 가 이 선언을 실행한다. 음악만의 문제가 아니다 —
채팅 앱도 좁아지면 시각과 채널명 중 무엇을 버릴지 정해야 한다.

```
음악 목록                       좁아지는 순서
제목      Min 14 Max 58 Drop 0   ← 절대 안 버린다
아티스트   Min 10 Max 26 Drop 2
재생수    Min  3        Drop 3   ← 제일 먼저 버린다
길이      Min  4        Drop 1
```

### 모드는 입력창 자신이 말한다

`shift+tab` 이 두 모드를 왕복하고, **커서 바로 앞의 글자와 테두리 색**이
지금 어느 쪽인지다.

```
 ╭──────────────────────────────────────────────╮   ← 딥톤 #A8253F
 │ Ask AI  something quiet                      │
 ╰──────────────────────────────────────────────╯

 ╭──────────────────────────────────────────────╮   ← 회색 #2E2E36
 │ Search  oasis                                │
 ╰──────────────────────────────────────────────╯
```

| | Ask AI | Search |
|---|---|---|
| 프롬프트 글자 | `Ask AI` — **브랜드 색** | `Search` — 회색 |
| 테두리 | 딥톤 | 회색 |

**프라이머리 색은 Ask AI 만 쓴다.** 모드가 둘이면 둘 다 강조할 이유가 없고,
기본값이 어느 쪽인지도 색이 말한다.

처음에는 입력창 **아래에 한 줄**을 두어 `› Ask  ⌕ Search  shift+tab` 을
띄웠다. 버린 이유는 두 가지다.

1. **자리를 상시로 먹는다.** 이 문서 전체가 반대하는 것이다
2. **말할 자리가 틀렸다.** 모드가 바꾸는 것은 "친 글자의 뜻"이므로,
   그것을 말할 가장 좋은 자리는 글자를 치는 바로 그 자리다

기호(`›` · `⌕`)가 아니라 **글자**를 쓰는 이유도 같다. 기호는 배워야 알고,
한 번 배워도 둘을 헷갈린다. 여덟 칸을 내주고 애매함을 없앤다.
두 프롬프트의 폭을 같게 맞춰서(`Ask AI  ` · `Search  `) 모드를 바꿔도
글자가 시작하는 칸이 흔들리지 않는다.

두 줄이던 호스트가 네 줄이 됐다 — 테두리 위아래가 늘었다. 대신 입력창
아래의 룰이 사라졌으므로, 실제로 늘어난 것은 **한 줄**이다.

### `shift+tab` 을 앱에게서 가져왔다

원래 음악 앱의 **이전 섹션**이었다. 그것이 있던 이유는 섹션이 열 개를 넘는데
(플레이리스트가 전부 섹션이다) **바로 가는 길이 없었기** 때문이다. 앞뒤로
더듬는 키는 없는 길을 때우는 것이지 그 자체로 기능이 아니었다.

그래서 섹션마다 `/` 명령을 냈다 — `/artists` `/albums` `/songs` `/recent`
`/queue` `/unplayed`, 그리고 플레이리스트마다 이름에서 깎은 것 하나씩.
바로 갈 수 있으면 뒤로 한 칸씩 갈 일이 없다. `tab`(다음)만 남는다.

**이것이 이 껍데기가 키를 늘리는 방식이다.** 새 키를 얹기 전에, 먼저
`/` 로 대신할 수 있는 키가 있는지 본다.

### 앱 전환에 전용 키를 두지 않는다

터미널은 키 이벤트가 아니라 바이트를 보낸다. `Tab` 은 ASCII `0x09` 이고
**`ctrl+I` 와 같은 바이트**여서, `ctrl+tab` 은 구별되는 시퀀스가 없다.
[kitty 키보드 프로토콜](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)
이 있어야 하는데 **Terminal.app 은 지원하지 않는다** (Ghostty·iTerm2·kitty·
WezTerm·Alacritty 는 됨).

**터미널에 따라 되다 안 되다 하는 키는 없는 것만 못하다.**

그리고 애초에 새 키가 필요 없다. `/music` 처럼 팔레트에 있으면 된다 —
사이드바를 없앤 것과 같은 이유다.

### 전환은 cmd+tab 에 가깝다

앱은 시작할 때 전부 켜져서 **끝까지 살아 있고, 화면만 갈아끼운다.**
그래서 채팅을 보는 중에도 음악은 계속 재생되고, 음악을 보는 중에도
안 읽은 메시지가 쌓인다. 상태줄이 그것을 계속 보여준다.

### 다만 "살아 있다"와 "장치를 잡고 있다"는 다르다

배경에서 계속 도는 것이 맞는 앱이 있고(재생), 그러면 안 되는 앱이 있다.
카메라나 마이크를 쓰는 앱은 **안 보는 동안 잡고 있으면 초록불이 세션 내내
켜져 있다.** 그것이 카메라 앱을 만들어 보고 알게 된 것이다(§7).

그래서 화면이 오갈 때 `app.FocusMsg` / `app.BlurMsg` 가 간다. 계약의
메서드가 아니라 메시지인 이유는 신경 쓸 앱만 받으면 되기 때문이다 —
음악은 이것을 무시하고 지금처럼 배경에서 계속 산다.

### 관통하는 원칙

```
화면에 상시로 자리를 주지 않는다. 필요할 때 입력창에서 불러낸다.
```

이 한 줄에서 아래가 전부 따라 나온다.

| 결정 | 근거 |
|---|---|
| 사이드바를 없앤다 | "갈 수 있는 곳"은 상시로 볼 필요가 없다. `/` 가 보여준다 |
| 검색 화면이 없다 | `ctrl+f` 로 지금 목록을 거른다 |
| 명령 팔레트가 입력창 **아래**에 뜬다 | 본문을 밀어내지 않는다. 고르는 동안 보던 것이 그대로 있다 |
| 도움말도 같은 자리 | 같은 이유 |

**사이드바는 상시 17칸(80칸 창의 21%)을 먹는다.** 그 대가로 얻는 것이
"목록을 항상 본다"인데, 터미널에서는 가로가 세로보다 귀하다.

### 팔레트는 본문을 밀어내지 않는다

처음에는 본문 자리를 통째로 빌려 썼다. 그런데 명령을 고르는 동안 보고
있던 목록이 사라져 **맥락을 잃고**, 눈도 화면 위아래를 왕복해야 했다.

입력창 바로 아래에 붙이면 둘 다 사라진다. agentic CLI 의 관례이기도 하다.

```
 ▌ Please Wait for Me          Busker Busker   177  1:21   ← 본문 그대로
   Peanut butter Sandwich       jisokuryClub    36  3:51
 ─────────────────────────────────────────────────────────
 › /
 ▌ /queue                        jump to the current queue  ← 여기
   /unplayed             tracks you added but never played
 ─────────────────────────────────────────────────────────
 Recently Added · 157
```

목록 높이 상한(14줄) 덕분에 **보통 크기의 터미널에서는 본문이 한 줄도
안 밀린다.**

## 2-B. 로그 — 호스트의 세 번째 자산

입력의 짝이다. **입력이 전역이면 출력도 전역이어야 한다.**

한 문장이 여러 앱에 갈 수 있으므로("조용한 거 틀고 슬랙도 꺼줘")
대화는 **어느 앱에도 속하지 않는다.** 앱을 바꿔도 이어져야 하고,
여러 앱에 걸친 요청의 결과가 착지할 곳도 여기뿐이다.

```
문장을 만드는 것은 앱,  보관하고 보여주는 것은 호스트
      ↕                        ↕
프로세스가 stdout 에 쓰고,  터미널이 스크롤백을 갖는다
```

| | |
|---|---|
| `›` | 사용자가 한 말 |
| `▸ 앱이름` | 앱이 한 말. **앱이 하나뿐이면 이름 생략** |
| `▸` (앰버) | 실패. 실패도 대화의 일부다 |
| 자리 | **입력창 바로 위.** 팔레트는 바로 아래 |
| 평소 | 마지막 한 줄만. 기다리는 중이면 방금 한 말 + 스피너 |
| `ctrl+j` | 펼침 (최대 8줄) |
| `ctrl+o` | **가장 최근 응답이 무슨 일을 했는지** |
| 보관 | 세션 동안만. 저장하지 않는다 |

### 상세 — "무슨 일이 있었나"

`ctrl+o` 로 가장 최근 응답을 펼치면 그 요청이 한 일이 보인다.

```
▸ 조용한 곡들 중에서 최근에 거의 안 들은 트랙을 중심으로 25분에 맞췄어요
    candidates 195 → 6 tracks · 24 min
     1. Babys          추가한 지 31일 됐지만 아직 0회 재생인…
     2. Woods          같은 EP에서 아직 한 번도 재생하지 않은…
    gpt-5.5 · 5.0s · ↑10.6k ↓273 · $0.0106
```

**"AI 가 무엇을 생각했나"는 담을 수 없다** — 모델이 추론 과정을 돌려주지
않는다. 대신 후보가 몇 개였고 무엇을 왜 골랐고 얼마나 걸리고 얼마 썼는지는
전부 우리가 안다.

가장 최근 하나만 펼친다. 전부 펼치면 본문이 사라진다.

### 곡별 근거는 본문에 두지 않는다

8곡짜리 큐에서 근거 8개를 다 읽는 사람은 없고, 한 줄로 하나만 보여주면
나머지 일곱은 어차피 안 보인다.

| | 어디 |
|---|---|
| 큐 전체 한 문장 | **로그** — 평소 보이는 한 줄 |
| 곡마다의 근거 | **상세** — `ctrl+o` 로 열어 본다 |

## 3. 앱의 의무

### 3-1. 앱은 자기 키 바인딩을 만들지 않는다

하고 싶은 것이 있으면 `Commands()` 로 등록한다.

앱이 각자 단축키를 만들면 조작법이 앱마다 달라지고, 그러면 이것은
그냥 tmux 가 된다. **처음 여는 앱에서도 `/` 를 누르면 뭘 할 수 있는지 보이고,
`shift+tab` 으로 찾고, `tab` 으로 넘길 수 있어야 한다.**

### 3-2. 앱은 자기 크기를 기억하지 않는다

`View(width, height)` 로 그릴 때마다 받는다.
`WindowSizeMsg` 를 자식에게 전달하고 각자 기억하게 하면 상태가 늘고 어긋난다.

### 3-3. 앱은 배경에서도 상태를 보고한다

`Status()` 와 `Badge()` 는 포커스가 없어도 호출된다.

## 4. 인터페이스

`internal/app/app.go` 참조. 각 항목의 근거는 실측이나 조사에서 나왔다.

| 항목 | 왜 이 모양인가 |
|---|---|
| `Update` 가 `App` 을 반환 | `tea.Model` 을 반환하면 호스트가 메시지마다 타입 단언을 해야 한다. Bubble Tea 에서 반복 지적되는 함정 |
| `View(w, h)` | 위 3-2 |
| `Init(send func(tea.Msg))` | Music.app 은 폴링이지만 채팅은 **저쪽에서 밀어 넣는다**(Socket Mode). 이벤트 루프 밖에서 메시지를 넣을 통로가 없으면 그런 앱을 담을 수 없다 |
| `Ready() error` | 앱마다 관문이 다르다. 음악은 macOS 자동화 권한, 채팅은 로그인 |
| `Description()` | 라우터가 "이 문장이 어느 앱 것인지" 판단하는 유일한 근거 |
| `Filter(query) App` | 검색은 즉시 반영되어야 하므로 `Cmd` 를 돌려주지 않는다 |
| `Back() (App, bool)` | `esc` 는 호스트의 키지만 하는 일이 "한 단계씩 물러난다"이다. 앱이 자기 안에 단계를 갖고 있으면(음악의 아티스트 파고들기) 그 사슬의 한 칸이 된다. `esc` 를 통째로 넘기지 않는 이유는 앱마다 물러나는 뜻이 달라지기 때문이다 |

## 5. 라우팅 — 작은 라우터를 항상 먼저 부른다

한 문장을 받아 어느 앱이 답할지 정하는 것이 호스트의 본체다.

```
입력:      "조용한 거 틀고 슬랙 꺼줘"      ← 앱이 둘일 때의 예시
컨텍스트:  앱 이름 + Description() (전부 합쳐 200토큰 남짓)
출력:      ["music", "slack"]
```

> **지금 담긴 앱은 `music` 하나다.** 그래서 이 경로는 실제로 돌지 않는다 —
> `dispatch()` 가 `len(apps) == 1` 에서 곧장 넘긴다. 그럼에도 남겨 두는 이유는
> 아래 "대부분의 경우 부르지 않는다" 가 설계의 결론이기 때문이다.
> 라우터는 예외 경로이지 기본 경로가 아니다.

**단어 매칭으로는 안 된다.** "조용한 거"에는 음악이라는 단어가 없고
"누가 나 찾았어?"에는 슬랙이라는 단어가 없다. 의도를 알아들어야 한다.

### 대부분의 경우 부르지 않는다

| 상황 | |
|---|---|
| 앱이 하나 | 답이 정해져 있다 |
| `@music 조용한 거` | 사용자가 지정했다 |
| `/queue` | 명령은 모델을 안 거친다 |

### 실측 (2026-09-09)

| | |
|---|---|
| 모델 | `gpt-5.4-mini` · 추론 `low` |
| 지연 | **약 1초** — `nano` 도 같다. 네트워크가 지배한다 |
| 정확도 | 문장 6개 전부 맞음 (한국어·영어·두 앱 동시·해당 없음) |

`"오늘 날씨 어때?"` 는 **빈 목록**을 돌려준다 — 모르겠다는 뜻이고,
호스트가 지금 보고 있는 앱으로 넘긴다.

### 틀려도 망하지 않는다

라우터가 못 고르거나 실패하면 지금 보고 있는 앱에게 준다.
엉뚱한 앱이 지목돼도 "그건 제가 할 수 있는 게 아닙니다"라고
로그에 남기고 끝이다.

**처음에는 "앱이 거절하면 그때 옮긴다"로 하려 했으나 두 가지 이유로 버렸다.**

1. 비싸다 — 음악 앱이 7초·$0.01 을 쓰고 "내 거 아님"이라고 하면 그 값을 버린다
2. **표현을 못 한다** — `handled` 는 불리언이라 "두 앱 다"를 말할 수 없다

라우터는 1초다. 선곡이 7초이므로 얹어도 체감이 없고,
**여러 앱을 지목할 수 있다.** 지금 보고 있는 앱을 힌트로 주면 정확도도 올라간다.

### 여러 앱은 동시에 부른다

순서를 보장하지 않는다. "틀고 꺼줘"는 순서 의존이 없고,
순서가 필요한 요청("A 하고 나서 B")은 **지금 범위 밖**이다.
결과는 도착하는 대로 로그에 쌓인다.

## 6. 만들지 않는 것

[Zellij](https://zellij.dev/documentation/plugins.html) 가 정확히 "터미널
워크스페이스 + 플러그인"을 한다. 그런데 **WASM 플러그인 + Protocol Buffers +
샌드박스**다. 그것이 이 길의 끝이고, 우리는 거기 가지 않는다.

| 안 만드는 것 | 왜 |
|---|---|
| 화면 분할 | tmux 가 이미 한다. 한 번에 한 앱 |
| 플러그인 시스템 | **앱은 컴파일 타임 등록.** 확장성을 여는 순간 Zellij 의 무게가 따라온다 |
| 프로세스 분리 · IPC | 같은 프로세스 함수 호출로 충분하다 |
| 알림 인터럽트 | 지금은 `Badge()` 숫자만. "어디까지 방해해도 되는가"는 답이 정해지지 않은 문제라 미뤄둔다 |

## 7. 앱 목록

| 앱 | 바깥과 통신 | 관문 | 상태 |
|---|---|---|---|
| **music** | AppleScript (Music.app) | macOS 자동화 권한 | 구현됨 |

**하나다.** 이 제품은 Apple Music CLI 이고, 산출물 3종(`api/openapi.yml`,
`db/schema.dbml`, `docs/01`·`02`)이 정의하는 서비스도 음악 하나뿐이다.
문서가 말하지 않는 것을 화면이 말하게 두지 않는다.

### 그런데 왜 계약을 이렇게 넓게 잡았나

한때 `chat`(Slack · HTTPS + WebSocket)과 `camera`(AVFoundation 헬퍼 프로세스)를
같은 두 줄 아래에 넣어서 **돌려 봤기 때문이다.** 그 둘이 이 계약을 끌어냈다 —
`Init(send)` 는 밀어 넣는 앱(채팅)이, `FocusMsg`/`BlurMsg` 는 장치를 잡는
앱(카메라)이, 라우터는 "두 앱 다"를 말해야 하는 문장이 만들었다.

증거는 코드에 남아 있다. `host/twoapp_test.go` · `focus_test.go` 가 스텁 앱으로
그 경로를 그대로 검증한다. 두 앱은 `backup/tui-multiapp` 브랜치에 있다.

```
git checkout backup/tui-multiapp -- tui/internal/cameraapp
```

**통신 방식은 앱마다 다르고, 그 차이는 앱이 자기 안에서 감춘다.**
호스트는 앱이 AppleScript 를 쓰는지 HTTPS 를 쓰는지 모른다.
