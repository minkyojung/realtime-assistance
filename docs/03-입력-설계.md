# Apple Music CLI — 입력 설계

> 산출물 ③. PDF 3장 "UI 흐름"의 재료 — 화면 동작 방식 상세 설명.
> 작성일: 2026-09-08 (화, D1)

---

## 1. 원칙 — 자연어가 기본이다

```
입력창은 항상 활성이고, 접두어 없이 친 것은 전부 자연어로 간주한다.
```

Claude Code · Codex CLI · Gemini CLI 계열의 **agentic TUI** 관례를 그대로 따른다.
모드 전환(vim 식)을 두지 않는다. 이 서비스에서 사용자가 하는 주된 일은
재생 제어가 아니라 **큐를 짓고 고치는 대화**이기 때문이다.

> **재생 제어는 이미 해결돼 있다.** 맥북 키보드의 미디어 키(F7·F8·F9)가
> Music.app을 직접 제어한다. 우리가 키를 뺏을 이유가 없다.

---

## 2. 입력창은 하나지만 하는 일이 둘이다

같은 입력창이 프롬프트도 되고 검색도 되면 사용자가 **지금 무엇을 하는 중인지
알 수 없다.** 프롬프트를 치는데 목록이 사라지면 그것만으로 혼란이다.

그래서 모드를 명시하고, 기호와 사이드바가 그것을 말한다.

| 모드 | 기호 | 진입 | 목록 | Enter |
|---|---|---|---|---|
| **프롬프트** (기본) | `Ask AI` (브랜드 색) | `shift+tab` | **건드리지 않는다** | 요청 전송 |
| **검색** | `Search` (회색) | `shift+tab` · `ctrl+f` | **즉시 걸러진다** | 고른 곡 재생 |
| 명령 | `Ask AI` | `/` 로 시작 | 건드리지 않는다 | 로컬 실행 |

**`shift+tab` 이 두 모드를 왕복한다.** 모드가 둘뿐이라 사이클이 아니라
토글이고, **커서 앞의 글자와 입력창 테두리 색**이 지금 어느 쪽인지를 말한다.
기호가 아니라 글자를 쓴다 — 기호는 배워야 알고 둘을 헷갈린다.

`/` 는 모드가 아니다. 접두어가 스스로 설명하고 지우면 원래대로 돌아오므로,
별도 상태를 두지 않는다. 사이클에 넣으면 `/` 를 지웠을 때 무슨 모드인지
모호해진다.

검색 중에는 상태줄이 `Search · 20` 으로 바뀐다.
**목록이 왜 걸러졌는지가 화면 안에서 설명된다.**

### 한 번의 검색이 두 곳을 보여준다

```
Your Library · 80          ← 딥톤 머리글
  Wonderwall (Live at Knebworth…)   Oasis
  …                                        최대 창의 1/4 (3~8줄)
  + 73 more in Your Library                enter 로 편다

Apple Music · 25
  Wonderwall                        Oasis  +
  …                                        남는 자리 전부
```

**위 구역에 상한을 둔다.** 둘을 한 줄로 이어 놓았더니 앞이 길면 뒤가 화면
밖으로 밀렸다 — `a` 한 글자에 라이브러리 193곡이 걸리면 Apple Music 머리글이
194번째 줄이다. 결과는 오는데 아무도 못 본다.

자리를 지켜주는 쪽이 Apple Music 인 이유는 **거기가 검색으로만 닿는 곳**
이기 때문이다. 내 라이브러리는 `/songs`·`/artists`·섹션으로도 간다.

접힌 줄에도 머리글에도 커서가 서지 않으므로, `↓` 한 번이면 곧장 Apple Music
결과다. 숨은 줄을 지나칠 필요가 없다.

카탈로그가 설정되지 않았으면 검색 중에만 그 말을 한다 —
`Apple Music search is off · /setup to connect`. 안 쓸 기능의 실패를 첫
화면에서 읽게 할 이유는 없지만, **바깥을 찾는 중에 바깥이 닫혀 있으면
그것은 말해야 한다.**

### 설정은 셸이 아니라 파일에 산다

한때 자격 증명을 환경변수로만 받았다. 그것은 서버·컨테이너의 방식이고
데스크톱 CLI 에는 안 맞는다 — 터미널마다 다시 `export` 해야 하고, 셸을
안 거치고 띄우면(Finder·앱 번들·launchd) 아예 못 받고, 껐다 켜면 사라진다.
**실제로 어제 되던 검색이 오늘 조용히 꺼져 있었다.**

세 단으로 본다. 위가 항상 이기고, 아래로 갈수록 느슨하다.

| | | |
|---|---|---|
| ① | 환경변수 `AM_*` | 있으면 이긴다. CI·일회성 실험용 |
| ② | `~/.config/amcli/config.json` | 평소 경로. 셸과 무관하게 산다 |
| ③ | 같은 폴더의 `AuthKey_*.p8` | 자동 탐색 |

③이 이 경우에 특히 값이 크다. 애플이 키 파일을 **`AuthKey_<KEYID>.p8`** 로
내려주므로 **Key ID 를 파일명에서 읽을 수 있다.** p8 경로와 Key ID 가 저절로
채워지고, 사람이 적는 것은 **Team ID 하나**로 준다 — 그것이 `/setup` 이다.

키 파일이 둘이면 고르지 않는다. 잘못 고르면 401 이 뜨는데 그 원인이 여기라는
것은 아무도 못 찾는다.

**무엇을 어디에 두느냐가 이 설계의 핵심이다.**

| | 어디 | 왜 |
|---|---|---|
| p8 개인키 | 파일 `0600` | 내용을 설정 파일에 눕히지 않는다 |
| Key ID · Team ID | 설정 파일 | **비밀이 아니다.** 개발자 포털에 그냥 보이는 식별자 |
| Music User Token | **키체인** | 남의 계정을 여는 열쇠 |

비밀이 아닌 것을 키체인에 넣으면 쓸데없이 권한 프롬프트가 뜨고, 비밀을
평문 설정에 넣으면 새어 나간다.

`esc` 는 한 단계씩 물러난다 — 검색 나가기 → 입력 비우기 → 종료.

## 3. 입력 4채널

| 채널 | 접두 | 처리 | 지연 | 비용 |
|---|---|---|---|---|
| **자연어** | 없음 (기본) | 서버 → LLM | 초 단위 | 토큰 |
| **슬래시 명령** | `/` | 로컬·서버, **LLM 미경유** | 즉시 | 0 |
| **멘션** | `@` | 대상 참조 → 자연어에 첨부 | — | — |
| **키** | — | 로컬 | 즉시 | 0 |

**분리 기준**

| 성질 | 어디로 |
|---|---|
| 자주 하고 · 정확해야 하고 · 빨라야 함 | 슬래시 / 키 |
| 표현이 열려 있고 · 매번 다름 | 자연어 |

슬래시는 자연어의 축약이 **아니다.** 화면 전환을 자연어로 시키면
2초를 기다리고 토큰을 쓰게 되므로, 그것은 설계 실패다.

## 4. 슬래시 명령

`/` 를 치면 **목록 패널이 명령 목록으로 바뀐다.** 검색과 같은 방식이라
화면이 늘어나지 않고, 무엇을 칠 수 있는지가 눈앞에 보인다.
사이드바 맨 위에 `▌ / Commands` 가 떠서 목록이 왜 바뀌었는지 설명한다.

### 구현된 것

| 명령 | 인자 | 하는 일 |
|---|---|---|
| `/recent` `/artists` `/albums` `/songs` | — | 해당 섹션으로 이동 |
| `/<플레이리스트 이름>` | — | 그 플레이리스트로 이동 |
| `/queue` | — | 큐로 이동 |
| `/unplayed` | — | 담아두고 한 번도 재생하지 않은 곡 |
| `/setup` | `<team ID>` | 애플 뮤직 연결 — 사람이 적어야 하는 유일한 값 |
| `/save` | `<이름>` | 큐를 Apple Music 플레이리스트로 저장 (F9) |
| `/clear` | — | 큐 비우기 |
| `/cost` | — | 이 세션이 쓴 비용 |
| `/help` | — | 키·명령 목록 (`?` 로도 열린다) |

### 다음 단계로 미룬 것

| 명령 | 필요한 것 |
|---|---|
| `/rules` | 반응 수집(F4·F5) |
| `/shazam` | ShazamKit 헬퍼(F10) |
| `/sync` | 라이브러리 실시간 동기화 (현재는 빌드 시점 스냅샷) |

**전부 LLM을 거치지 않는다.** 이것이 체감 속도를 지탱하는 장치다.

### 도움말도 화면을 만들지 않는다

`?` 또는 `/help` 는 목록 패널을 잠시 빌려 쓴다. 오버레이를 따로 만들지 않는다.
**검색·명령·도움말이 전부 같은 패널을 쓴다** — 화면이 늘지 않는 이유다.

## 5. 자연어 — 서버가 분류하는 의도

자연어 입력은 서버에서 **의도 분류 → 해당 처리**로 갈라진다. (AI 레이어 L2)

| 의도 | 예시 | 처리 |
|---|---|---|
| **큐 생성** | "새벽 코딩용, 가사 없는 걸로" | L2 조건 추출 → L3 선곡 → L4 근거 |
| **큐 재편성** | "좀 더 조용한 걸로", "이 아티스트 빼줘" | **현재 큐를 함께 넘긴다.** 새 큐인지 수정인지는 모델이 문장을 보고 판단 |
| **근거 질의** | "이거 왜 골랐어?" | L4 결과 재설명 (재선곡 없음) |
| **반응 표명** | "이건 별로야", "이런 거 좋아" | `Reaction` 기록 → 큐 즉시 반영 |
| **탐색 질의** | "2019년 여름에 듣던 느낌으로" | 재생 이력 기반 조건 추출 |

### `@` 멘션

| 형태 | 뜻 |
|---|---|
| `@Weightless 같은 걸로 8곡` | 특정 곡을 기준점으로 |
| `@Radiohead 중에 안 들은 거` | 아티스트로 후보 한정 |
| `@집중 플레이리스트에서` | 플레이리스트로 후보 한정 |

멘션은 **후보 집합을 좁히는 필터**로만 쓴다. 입력 중 자동완성으로 노출된다.

## 6. 키 바인딩 — 최소한만

| 키 | 동작 | 조건 |
|---|---|---|
| `Enter` | 입력 전송 | |
| `Ctrl+C` | 진행 중인 요청 취소 | 항상 |
| `Ctrl+J` | 대화 띠 접기 · 펴기 | 항상 |
| `Ctrl+L` | 화면 정리 | 항상 |
| `↑` `↓` | 입력 이력 | 입력창 포커스 |
| `Tab` | 다음 섹션 | 앱 안 |
| `Shift+Tab` | 모드 바꾸기 — `Ask AI` ⇄ `Search` | 앱 안 |
| `space` | 재생 / 일시정지 | **입력창이 비어 있을 때만** |
| `?` | 도움말 | 입력창이 비어 있을 때만 |

### 알파벳 단축키를 두지 않는 이유

`s`=스킵을 두면 *"sad한 곡으로"* 를 치는 순간 첫 글자가 스킵으로 먹힌다.
**입력창이 항상 활성인 구조에서 알파벳 단축키는 자연어와 반드시 충돌한다.**
그래서 `space`(문장을 공백으로 시작하는 일은 없다)와 `Ctrl` 조합만 남긴다.

## 7. 반응은 입력받지 않고 관찰한다

스킵을 키로 받지 않는다. Music.app이 이미 기록하고 있기 때문이다.

| 신호 | 수집 방법 | 해석 |
|---|---|---|
| 3초 내 이탈 | 재생 위치 폴링 (1초 주기) | **강한 부정** |
| 중간 이탈 | 폴링 | 약한 부정 |
| 완청 | 폴링 | 긍정 |
| 반복 재생 | `played count` 증가분 | 강한 긍정 |
| `loved` / 별점 | AppleScript 필드 | 명시적 긍정 |
| "이건 별로야" | 자연어 | 명시적 부정 |

> **사용자가 터미널을 보고 있지 않아도 데이터가 쌓인다.**
> 이것이 키 입력에 의존하는 방식보다 정확하고, 화면을 비우는 근거가 된다.

## 8. 지연 예산

입력창이 유일한 통로이므로 **응답 지연이 곧 UX**다.

| 동작 | 목표 | 수단 |
|---|---|---|
| 슬래시 명령 | < 100ms | LLM 미경유 |
| 큐 생성 | 첫 곡 < 2s | 무드 태그 사전 캐시(L1), 부분 스트리밍 |
| 큐 재편성 | < 2s | 후보를 현재 큐로 한정 |
| 근거 생성 | 곡당 < 300ms | 짧은 생성, 병렬 |
| Shazam 인식 | < 5s | ShazamKit 표준 |

**완화 장치 3가지**

1. **L1 무드 태깅은 배치 1회 + 캐시** — 실시간 경로에 태깅을 두지 않는다
2. **낙관적 렌더** — 요청 즉시 `Thinking...`, 결과는 스트리밍으로 흘린다
3. **재생은 절대 막지 않는다** — 큐 생성 중에도 현재 곡은 계속 재생된다
4. **재편성으로 지금 곡이 살아남으면 다시 틀지 않는다** — 듣던 곡이 처음으로
   되감기는 것만큼 짜증나는 것이 없다

## 9. 명령 → 화면 전환 맵 (UI 흐름도 초안)

```
                        ┌──────────────┐
              /queue    │  S1 재생 뷰   │  ← 시작 화면
           ┌───────────▶│   (기본)     │◀──────────┐
           │            └──┬─┬─┬─┬─────┘           │
           │               │ │ │ │                 │ [큐에 넣기]
      /graveyard      /diagnose │ /shazam          │
           │               │ │ │ │                 │
           ▼               ▼ │ │ ▼                 │
    ┌─────────────┐  ┌──────────┐  ┌──────────────┴┐
    │  S2 묘비     │  │ S3 진단  │  │ S5 인식 결과   │
    └──────┬──────┘  └────┬─────┘  └───────────────┘
           │              │ /sync        │
     [비슷한 신곡]         └──▶ 재동기화   │ [라이브러리에 추가]
           │                             ▼
           ▼                       (Apple Music)
     (카탈로그 조회)
                    /rules
    ┌─────────────┐◀────────── S1
    │ S4 취향 규칙 │
    └─────────────┘

    S6 예외 상태 — 위 모든 화면에서 조건 충족 시 오버레이
```

**슬래시 명령 목록이 곧 화면 전환 맵이다.** 흐름도를 따로 상상할 필요가 없고,
명령이 늘면 화면이 늘어나므로 누락이 구조적으로 방지된다.

## 10. 언어 정책

```
시스템 언어는 영어. 사용자·AI 가 만든 내용은 사용자의 언어.
```

| 구분 | 언어 | 예 |
|---|---|---|
| **레이블 · 상태 · 도움말** | **영어 (고정)** | `Up next` · `● Playing` · `8 tracks · 33 min · 7 never played` |
| 슬래시 명령 | 영어 (고정) | `/graveyard` `/diagnose` |
| 곡 제목 · 아티스트 | 원본 그대로 | `Jirisan Breeze` · `Perth` |
| 사용자 입력 | 사용자가 친 대로 | `something even quieter` |
| AI 가 만든 선정 근거 | **기본 영어**, 사용자 언어를 따라감 | `Added Jul 2026, never played once` |

**기본 동작 언어는 영어다.** 사용자가 다른 언어로 물으면 근거도 그 언어로
따라가지만, 화면의 뼈대는 언제나 영어로 고정된다.
터미널 도구의 관례를 따른 것이다.

## 11. 색

```
빨강은 "소리가 나고 있다"는 뜻으로만 쓴다. 침묵은 회색이다.
```

| 색 | 쓰는 곳 |
|---|---|
| `#FA002C` (Apple Music red) | **앨범 아트** · 재생 중 표시 · 진행 바 · 입력 프롬프트 · 커서 · **되살리기 액션** |
| `#7A0A1E` 딥톤 | 헤더 구분선 · 큐 번호 — 반복되는 작은 요소로 리듬을 만든다 |
| 회색 | 미재생 곡 — **색이 없다는 것 자체가 죽어 있다는 뜻** |
| 앰버 `#E8A33D` | 경고 |
| 채워진 빨강 배지 | 오류 |

묘비 화면(S2)은 통째로 무채색이고, 되살리는 순간 색이 돌아온다.

**채워진 빨강은 오류에만 쓴다. 나머지 빨강은 선과 글자다.**
이 규칙이 서 있으면 브랜드 색을 늘려도 의미가 흐려지지 않는다.

앨범 아트가 브랜드 색을 크게 쓸 수 있는 유일한 자리다. 원래 앨범 커버가
놓이는 곳이라 색면이 커도 경보로 읽히지 않는다.

예외로 진단 화면(S3)의 미재생 비율 숫자에는 빨강을 쓴다. 그 숫자가
이 서비스가 주장하는 문제 자체이므로 경보로 읽혀야 한다.

## 12. 발견 가능성

키 바인딩과 명령은 발견 가능성이 0에 가깝다. 세 곳에서 노출한다.

| 장치 | 위치 |
|---|---|
| `/` 입력 시 명령 팔레트 자동 표시 | 입력창 위 |
| 빈 입력창 placeholder — *"What do you want to hear?  /  commands   ?  help"* | 입력창 |
| `/help` · `?` 전체 목록 | 오버레이 |

첫 실행 시에는 입력 대신 **S3 진단 화면을 먼저 보여준다.**
사용자가 "담아둔 곡의 3분의 1은 한 번도 듣지 않았다"를 확인한 뒤에
첫 자연어 입력을 하도록 유도하는 것이, 이 서비스의 의도를 가장 짧게 전달한다.
