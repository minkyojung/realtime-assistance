# Apple Music CLI — 입력 설계

> 산출물 ③. PDF 3장 "UI 흐름"의 재료 — 화면 동작 방식 상세 설명.
> 작성일: 2026-09-08 (화, D1)

---

## 1. 원칙 — 자연어가 기본이다

```
입력창은 항상 활성이고, 접두어 없이 친 것은 전부 자연어로 간주한다.
```

Claude Code · Codex CLI · Gemini CLI 계열의 **agentic TUI** 관례를 그대로 따른다.
모드 전환(vim 식)을 두지 않는다. 이 서비스에서 사용자가 하는 주된 일은
재생 제어가 아니라 **큐를 짓고 고치는 대화**이기 때문이다.

> **재생 제어는 이미 해결돼 있다.** 맥북 키보드의 미디어 키(F7·F8·F9)가
> Music.app을 직접 제어한다. 우리가 키를 뺏을 이유가 없다.

---

## 2. 입력창은 하나지만 하는 일이 둘이다

같은 입력창이 프롬프트도 되고 검색도 되면 사용자가 **지금 무엇을 하는 중인지
알 수 없다.** 프롬프트를 치는데 목록이 사라지면 그것만으로 혼란이다.

그래서 모드를 명시하고, 기호와 사이드바가 그것을 말한다.

| 모드 | 기호 | 진입 | 목록 | Enter |
|---|---|---|---|---|
| **프롬프트** (기본) | `›` | — | **건드리지 않는다** | 요청 전송 |
| **검색** | `⌕` | `ctrl+f` | **즉시 걸러진다** | 고른 곡 재생 |
| 명령 | `›` | `/` 로 시작 | 건드리지 않는다 | 로컬 실행 |

검색 중에는 사이드바 맨 위에 `▌ ⌕ Search` 가 뜨고 섹션 선택 표시가 꺼진다.
**목록이 왜 걸러졌는지가 화면 안에서 설명된다.**

`esc` 는 한 단계씩 물러난다 — 검색 나가기 → 입력 비우기 → 종료.

## 3. 입력 4채널

| 채널 | 접두 | 처리 | 지연 | 비용 |
|---|---|---|---|---|
| **자연어** | 없음 (기본) | 서버 → LLM | 초 단위 | 토큰 |
| **슬래시 명령** | `/` | 로컬·서버, **LLM 미경유** | 즉시 | 0 |
| **멘션** | `@` | 대상 참조 → 자연어에 첨부 | — | — |
| **키** | — | 로컬 | 즉시 | 0 |

**분리 기준**

| 성질 | 어디로 |
|---|---|
| 자주 하고 · 정확해야 하고 · 빨라야 함 | 슬래시 / 키 |
| 표현이 열려 있고 · 매번 다름 | 자연어 |

슬래시는 자연어의 축약이 **아니다.** 화면 전환을 자연어로 시키면
2초를 기다리고 토큰을 쓰게 되므로, 그것은 설계 실패다.

## 4. 슬래시 명령

| 명령 | 인자 | 하는 일 | 결과 화면 | LLM |
|---|---|---|---|---|
| `/graveyard` | `[기준]` 기본 `never` | 미재생 곡 목록 | S2 | ✗ |
| `/diagnose` | — | 라이브러리 재생률 진단 | S3 | ✗ |
| `/rules` | — | 취향 규칙 목록 | S4 | ✗ |
| `/shazam` | — | 지금 들리는 곡 인식 | S5 | ✗ |
| `/save` | `<이름>` | 현재 큐를 플레이리스트로 저장 | S1 | ✗ |
| `/sync` | — | 라이브러리 재동기화 | S3 | ✗ |
| `/queue` | — | 큐 전체 펼치기 | S1 | ✗ |
| `/sessions` | `[id]` | 세션 목록 · 재개 | S1 | ✗ |
| `/cost` | — | 토큰·비용 내역 | S1 | ✗ |
| `/help` | — | 명령·키 목록 | S1 | ✗ |

**전부 LLM을 거치지 않는다.** 이것이 체감 속도를 지탱하는 장치다.

## 5. 자연어 — 서버가 분류하는 의도

자연어 입력은 서버에서 **의도 분류 → 해당 처리**로 갈라진다. (AI 레이어 L2)

| 의도 | 예시 | 처리 |
|---|---|---|
| **큐 생성** | "새벽 코딩용, 가사 없는 걸로" | L2 조건 추출 → L3 선곡 → L4 근거 |
| **큐 재편성** | "좀 더 조용한 걸로", "이 아티스트 빼줘" | 현재 큐를 컨텍스트로 재정렬 |
| **근거 질의** | "이거 왜 골랐어?" | L4 결과 재설명 (재선곡 없음) |
| **반응 표명** | "이건 별로야", "이런 거 좋아" | `Reaction` 기록 → 큐 즉시 반영 |
| **탐색 질의** | "2019년 여름에 듣던 느낌으로" | 재생 이력 기반 조건 추출 |

### `@` 멘션

| 형태 | 뜻 |
|---|---|
| `@Weightless 같은 걸로 8곡` | 특정 곡을 기준점으로 |
| `@Radiohead 중에 안 들은 거` | 아티스트로 후보 한정 |
| `@집중 플레이리스트에서` | 플레이리스트로 후보 한정 |

멘션은 **후보 집합을 좁히는 필터**로만 쓴다. 입력 중 자동완성으로 노출된다.

## 6. 키 바인딩 — 최소한만

| 키 | 동작 | 조건 |
|---|---|---|
| `Enter` | 입력 전송 | |
| `Ctrl+C` | 진행 중인 요청 취소 | 항상 |
| `Ctrl+O` | 큐 · 긴 출력 펼치기 | 항상 |
| `Ctrl+L` | 화면 정리 | 항상 |
| `↑` `↓` | 입력 이력 | 입력창 포커스 |
| `Tab` | 자동완성 (명령 · 멘션) | 입력 중 |
| `space` | 재생 / 일시정지 | **입력창이 비어 있을 때만** |
| `?` | 도움말 | 입력창이 비어 있을 때만 |

### 알파벳 단축키를 두지 않는 이유

`s`=스킵을 두면 *"sad한 곡으로"* 를 치는 순간 첫 글자가 스킵으로 먹힌다.
**입력창이 항상 활성인 구조에서 알파벳 단축키는 자연어와 반드시 충돌한다.**
그래서 `space`(문장을 공백으로 시작하는 일은 없다)와 `Ctrl` 조합만 남긴다.

---

## 7. 반응은 입력받지 않고 관찰한다

스킵을 키로 받지 않는다. Music.app이 이미 기록하고 있기 때문이다.

| 신호 | 수집 방법 | 해석 |
|---|---|---|
| 3초 내 이탈 | 재생 위치 폴링 (1초 주기) | **강한 부정** |
| 중간 이탈 | 폴링 | 약한 부정 |
| 완청 | 폴링 | 긍정 |
| 반복 재생 | `played count` 증가분 | 강한 긍정 |
| `loved` / 별점 | AppleScript 필드 | 명시적 긍정 |
| "이건 별로야" | 자연어 | 명시적 부정 |

> **사용자가 터미널을 보고 있지 않아도 데이터가 쌓인다.**
> 이것이 키 입력에 의존하는 방식보다 정확하고, 화면을 비우는 근거가 된다.

---

## 8. 지연 예산

입력창이 유일한 통로이므로 **응답 지연이 곧 UX**다.

| 동작 | 목표 | 수단 |
|---|---|---|
| 슬래시 명령 | < 100ms | LLM 미경유 |
| 큐 생성 | 첫 곡 < 2s | 무드 태그 사전 캐시(L1), 부분 스트리밍 |
| 큐 재편성 | < 2s | 후보를 현재 큐로 한정 |
| 근거 생성 | 곡당 < 300ms | 짧은 생성, 병렬 |
| Shazam 인식 | < 5s | ShazamKit 표준 |

**완화 장치 3가지**

1. **L1 무드 태깅은 배치 1회 + 캐시** — 실시간 경로에 태깅을 두지 않는다
2. **낙관적 렌더** — 요청 즉시 `Thinking...`, 결과는 스트리밍으로 흘린다
3. **재생은 절대 막지 않는다** — 큐 생성 중에도 현재 곡은 계속 재생되고 `space`가 듣는다

## 9. 명령 → 화면 전환 맵 (UI 흐름도 초안)

```
                        ┌──────────────┐
              /queue    │  S1 재생 뷰   │  ← 시작 화면
           ┌───────────▶│   (기본)     │◀──────────┐
           │            └──┬─┬─┬─┬─────┘           │
           │               │ │ │ │                 │ [큐에 넣기]
      /graveyard      /diagnose │ /shazam          │
           │               │ │ │ │                 │
           ▼               ▼ │ │ ▼                 │
    ┌─────────────┐  ┌──────────┐  ┌──────────────┴┐
    │  S2 묘비     │  │ S3 진단  │  │ S5 인식 결과   │
    └──────┬──────┘  └────┬─────┘  └───────────────┘
           │              │ /sync        │
     [비슷한 신곡]         └──▶ 재동기화   │ [라이브러리에 추가]
           │                             ▼
           ▼                       (Apple Music)
     (카탈로그 조회)
                    /rules
    ┌─────────────┐◀────────── S1
    │ S4 취향 규칙 │
    └─────────────┘

    S6 예외 상태 — 위 모든 화면에서 조건 충족 시 오버레이
```

**슬래시 명령 목록이 곧 화면 전환 맵이다.** 흐름도를 따로 상상할 필요가 없고,
명령이 늘면 화면이 늘어나므로 누락이 구조적으로 방지된다.

## 10. 언어 정책

```
시스템 언어는 영어. 사용자·AI 가 만든 내용은 사용자의 언어.
```

| 구분 | 언어 | 예 |
|---|---|---|
| **레이블 · 상태 · 도움말** | **영어 (고정)** | `Up next` · `● Playing` · `8 tracks · 33 min · 7 never played` |
| 슬래시 명령 | 영어 (고정) | `/graveyard` `/diagnose` |
| 곡 제목 · 아티스트 | 원본 그대로 | `Jirisan Breeze` · `Perth` |
| 사용자 입력 | 사용자가 친 대로 | `something even quieter` |
| AI 가 만든 선정 근거 | **기본 영어**, 사용자 언어를 따라감 | `Added Jul 2026, never played once` |

**기본 동작 언어는 영어다.** 사용자가 다른 언어로 물으면 근거도 그 언어로
따라가지만, 화면의 뼈대는 언제나 영어로 고정된다.
터미널 도구의 관례를 따른 것이다.

## 11. 색

```
빨강은 "소리가 나고 있다"는 뜻으로만 쓴다. 침묵은 회색이다.
```

| 색 | 쓰는 곳 |
|---|---|
| `#FA002C` (Apple Music red) | **앨범 아트** · 재생 중 표시 · 진행 바 · 입력 프롬프트 · 커서 · **되살리기 액션** |
| `#7A0A1E` 딥톤 | 헤더 구분선 · 큐 번호 — 반복되는 작은 요소로 리듬을 만든다 |
| 회색 | 미재생 곡 — **색이 없다는 것 자체가 죽어 있다는 뜻** |
| 앰버 `#E8A33D` | 경고 |
| 채워진 빨강 배지 | 오류 |

묘비 화면(S2)은 통째로 무채색이고, 되살리는 순간 색이 돌아온다.

**채워진 빨강은 오류에만 쓴다. 나머지 빨강은 선과 글자다.**
이 규칙이 서 있으면 브랜드 색을 늘려도 의미가 흐려지지 않는다.

앨범 아트가 브랜드 색을 크게 쓸 수 있는 유일한 자리다. 원래 앨범 커버가
놓이는 곳이라 색면이 커도 경보로 읽히지 않는다.

예외로 진단 화면(S3)의 미재생 비율 숫자에는 빨강을 쓴다. 그 숫자가
이 서비스가 주장하는 문제 자체이므로 경보로 읽혀야 한다.

## 12. 발견 가능성

키 바인딩과 명령은 발견 가능성이 0에 가깝다. 세 곳에서 노출한다.

| 장치 | 위치 |
|---|---|
| `/` 입력 시 명령 팔레트 자동 표시 | 입력창 위 |
| 빈 입력창 placeholder — *"What do you want to hear?  /  commands   ?  help"* | 입력창 |
| `/help` · `?` 전체 목록 | 오버레이 |

첫 실행 시에는 입력 대신 **S3 진단 화면을 먼저 보여준다.**
사용자가 "담아둔 곡의 3분의 1은 한 번도 듣지 않았다"를 확인한 뒤에
첫 자연어 입력을 하도록 유도하는 것이, 이 서비스의 의도를 가장 짧게 전달한다.
