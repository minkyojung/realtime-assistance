# §4. 데이터 모델 설계

> PDF 4장. 배점 20점.
> 전체 정의는 `판교_3반_{이름}_AppleMusic-DB.dbml` 에 있고, 여기에는 요약을 싣는다.

---

## 4-1. 설계 원칙 — 화면에서 컬럼을 뽑았다

**화면에 보이는 값을 먼저 전부 적고, 그중 "저장해야 하는 것"만 컬럼으로 만들었다.**
반대 순서로 하면 화면에 있는 데이터가 ERD 에 없는 일이 생긴다.

값은 넷으로 나뉘었다.

| 분류 | 예 | 컬럼이 되는가 |
|---|---|---|
| **저장** | 곡 제목 · 재생 횟수 · 마지막 재생일 | **된다** |
| 실시간 | 재생 위치 · 앨범 커버 · 섞기 상태 | 안 된다 — 서버가 Music.app 에 그때그때 묻는다 |
| 계산 | 진행바 · "3년 전" · 항목 수 | 안 된다 — 다른 값으로 만든다 |
| 고정 | 도움말 문구 · 명령 이름 | 안 된다 |

**실시간 값을 저장하지 않는 이유:** 사용자가 Music.app 에서 직접 섞기를 켤 수
있다. 우리가 기억한 값은 그 순간 거짓말이 된다. 어긋난 값은 없는 값보다 나쁘다.

## 4-2. 엔티티 11개

| # | 테이블 | 무엇인가 | 화면 |
|---|---|---|---|
| 1 | `artist` | 아티스트 | W3 묶음 · 모든 곡 행 |
| 2 | `album` | 앨범 | W3 묶음 · 지금 재생 |
| 3 | `track` | **곡** — 가장 많이 읽히는 표 | W2~W6 전부 |
| 4 | `playlist` | 플레이리스트 | 목록 구역 |
| 5 | `playlist_track` | 플레이리스트에 담긴 곡과 그 순서 | 목록 구역 |
| 6 | `queue` | 재생 큐 하나 | W4 |
| 7 | `queue_item` | 큐에 담긴 곡 · **선정 근거** | W4 · 대화 띠 |
| 8 | `turn` | 자연어 요청 한 건 · 토큰 · 비용 | 대화 띠 · 상태줄 |
| 9 | `message` | 대화 띠의 한 줄 | 대화 띠 |
| 10 | `play` | 곡이 끝난 사건 — **왜** 끝났나 | 없음 (아래 4-6) |
| 11 | `setting` | 이 기기의 설정 (한 행) | W1 홈 · W8 관문 |

## 4-3. 관계

```
artist ─1:N─▶ album ─1:N─▶ track
   └────────1:N──────────────┘

playlist ─1:N─▶ playlist_track ◀─N:1─ track      ← M:N (순서 있음)

queue ─1:N─▶ queue_item ◀─N:1─ track
                  ▲
                  └─1:N─ turn        (사람이 넣었으면 turn_id = NULL)

turn ─1:N─▶ message
track ─1:N─▶ play ◀─N:1─ queue_item
```

| 관계 | 종류 | 왜 |
|---|---|---|
| `artist` → `album` | 1:N | 한 아티스트가 여러 앨범 |
| `artist` → `track` | 1:N | 앨범 없는 싱글도 아티스트는 있다 |
| `album` → `track` | 1:N (**FK nullable**) | 앨범 없는 곡이 실제로 있다 |
| `playlist` ↔ `track` | **M:N** | 한 곡이 여러 플레이리스트에, 한 플레이리스트에 여러 곡 |
| `queue` → `queue_item` | 1:N | |
| `turn` → `queue_item` | 1:N (**FK nullable**) | AI 가 넣은 곡만 연결된다 |
| `turn` → `message` | 1:N | 한 요청이 여러 줄을 남길 수 있다 |
| `track` → `play` | 1:N | 같은 곡을 여러 번 듣는다 |

**M:N 은 `playlist ↔ track` 하나뿐이고, `playlist_track` 이 그것을 푼다.**
순서가 있어야 하므로 `(playlist_id, position)` 이 복합 기본키다.

## 4-4. 핵심 컬럼

### `track` — 이 서비스의 중심

| 컬럼 | 타입 | 제약 | 화면 |
|---|---|---|---|
| `id` | integer | **PK** | |
| `persistent_id` | varchar(32) | **not null, unique** | Music.app 동기화 키 |
| `title` | varchar(255) | not null | 제목 |
| `artist_id` | integer | **FK** → `artist.id`, not null | 아티스트 |
| `album_id` | integer | **FK** → `album.id`, **null 허용** | 앨범 |
| `genre` · `year` | varchar(64) · integer | null 허용 | 장르 · 연도 |
| `duration_ms` | integer | not null | 길이 |
| `play_count` | integer | not null, default 0 | 재생 횟수 |
| `added_at` | timestamp | null 허용 | 추가일 |
| **`last_played_at`** | timestamp | **null 허용** | **★ 아래 참조** |
| `in_library` | boolean | not null, default true | 목록 노출 여부 |
| `apple_music_id` | varchar(32) | null 허용 | Apple Music 보유 표시 대조 |

### ★ `last_played_at` — 화면 두 곳을 지탱하는 컬럼

```sql
last_played_at IS NULL   →   "담아두고 한 번도 재생하지 않은 곡"
```

- `Unplayed` 구역 전체가 이 조건 하나다 (W5)
- 재생 화면의 빨간 `never played` 경고가 같은 조건이다 (W2)

**서비스가 정의한 문제가 데이터 모델에서는 컬럼 하나의 `NULL` 로 나타난다.**
그래서 이 컬럼에 인덱스를 걸었다.

### ★ `queue_item.reason` — null 허용인 이유

AI 가 곡을 왜 골랐는지 적는 한 줄이다. **AI 가 근거를 못 만들어도 `null` 일 뿐
재생은 그대로 간다.** 근거가 없다고 음악이 멈추면 안 되기 때문이고, 이 결정이
스키마의 `null` 허용으로 남아 있다.

## 4-5. 저장하지 않기로 한 것

| 값 | 왜 안 두나 |
|---|---|
| 재생 위치 · 재생 여부 · 섞기 · 반복 · 볼륨 | 사용자가 Music.app 에서 직접 바꾼다. 매번 읽는다 |
| 앨범 커버 이미지 | 우리 것이 아니고, 1만 곡의 커버를 들고 있을 이유가 없다 |
| 가사 | LRCLIB 것이다. 판본마다 타이밍이 다르다 |
| 세션 누적 토큰 · 비용 | `turn` 을 합치면 나온다. 따로 두면 두 값이 어긋난다 |
| API 키 · 사용자 토큰 | macOS 키체인에 둔다. DB 에는 "붙어 있는가"만 남긴다 |
| 사용자 | 로그인 화면이 없다. 한 사람의 기기에서 도는 로컬 데몬이다 |

## 4-6. `play` — 화면이 없는 유일한 표

곡 하나가 끝난 사건을 적는다. 화면 어디에도 안 보인다.

**있는 이유:** Music.app 은 **무슨 일이 있었는지**만 센다 — 틀었다 3번,
넘겼다 2번. 그런데 **왜** 넘어갔는지는 세지 않고, 이 서비스에서 곡이 끝나는
이유는 넷이다.

| `ended_by` | 뜻 |
|---|---|
| `finished` | 끝까지 들었다 |
| `skipped` | 사람이 넘겼다 |
| `removed` | 큐에서 뺐다 |
| `replaced` | 큐를 갈아끼웠다 |

Music.app 의 스킵 수에는 이 넷이 뒤섞여 있다. 그것을 나누어 적는다.

**해석은 적지 않는다.** "일찍 나감" 같은 판정을 저장하면 기준을 바꿀 때
지난 것을 다시 계산할 수 없다. 3초가 맞는지 5% 가 맞는지는 아직 모른다.

**쓰이는 곳:** 다음 선곡(`POST /turns`)이 읽어서 최근에 넘긴 곡을 후보에서
덜어낸다. 화면 → API → ERD 사슬의 유일한 예외이며, 그래서 여기 적어 둔다.
