# Apple Music CLI — 액터 · 기능 · 화면

> 산출물 ②. PDF 2장 "시스템 액터 정의" + 3장 "UI 흐름"의 재료.
> 작성일: 2026-09-08 (화, D1) / 개정: Shazam(F10·F11) 반영
>
> **원칙: 모든 기능은 액터 한 명과 화면 한 곳에 반드시 매핑된다.**
> 매핑되지 않는 기능은 기능이 아니라 상상이므로 삭제한다.

---

## 1. 액터 4명

| 액터 | 누구인가 | 어떻게 접근하나 | 주 화면 |
|---|---|---|---|
| **A. 청취자** | 지금 음악을 듣고 있는 사람 | TUI | 재생 뷰 · 인식 결과 |
| **B. 취향 관리자** | 라이브러리를 손보는 사람 | TUI | 진단 · 안 듣는 곡 · 취향 규칙 |
| **C. AI 에이전트** | 코딩 에이전트 · 캘린더 · 음성 비서 | **API 직접 호출** | 없음 (화면 없이 동작) |
| **D. 외부 시스템** | Music.app · Apple Music API · ShazamKit | 서버가 호출 | — |

> **A와 B는 대개 같은 사람이다.** 하는 일과 시점이 달라 액터를 나눈다.
> 듣는 동안에는 판단을 미루고, 다 듣고 나서 라이브러리를 손본다.
>
> **C는 이 서비스의 설계 원칙이 만들어낸 액터다.** 서버는 TUI 의 백엔드가 아니라
> 도구 표면이므로, 에이전트는 A·B 와 **완전히 같은 API** 를 쓴다.
> 화면이 없다는 것이 이 액터의 정의다.

## 2. 액터별 기능

### A. 청취자

| # | 기능 | 화면 | 근거 |
|---|---|---|---|
| A1 | 자연어로 재생 큐를 요청한다 | S1 | F1 |
| A2 | 곡별 선정 근거를 확인한다 | S1 | F2 |
| A3 | 재생을 제어한다 | S1 | — |
| A4 | 큐를 되물어 재편성한다 | S1 | F3 |
| A5 | 반응을 남긴다 (스킵 관찰 + 자연어) | S1 | F4 |
| A6 | 현재 곡 정보와 앨범 아트를 본다 | S1 | — |
| A7 | 마음에 든 큐를 플레이리스트로 저장한다 | S1 | F9 |
| A8 | 이전 청취 세션을 재개한다 | S1 | — |
| A9 | 지금 들리는 곡을 인식한다 | S5 | F10 |

| # | 기능 | 화면 | 근거 |

| B3 | 미재생 곡(묘비) 목록을 훑는다 | S2 | F7 |
| B4 | 죽은 곡을 되살린다 (즉시 큐에 투입) | S2 | F7 |

| B6 | 죽은 곡을 실마리로 카탈로그 유사곡을 탐색한다 | S2 | F8 |

### C. AI 에이전트 — 화면 없이 API 로만

| # | 기능 | 엔드포인트 | 사람과 다른 점 |
|---|---|---|---|
| C1 | 의도로 큐를 요청한다 | `POST /sessions/{id}/turns` | 없음 — **완전히 같은 API** |
| C2 | 선정 근거를 받는다 | `GET /turns/{id}` | 화면 대신 JSON 으로 받는다 |
| C3 | 재생 상태를 조회한다 | `GET /sessions/{id}` | 같음 |
| C4 | 반응을 대신 기록한다 | `POST /queue-items/{id}/reactions` | `detectedBy` 로 구분 |
| C5 | 라이브러리 상태를 읽는다 | `GET /library/diagnosis` | 다른 워크플로의 컨텍스트로 쓴다 |

**모든 호출은 `queue_item.origin = agent` 로 남는다.**
그래서 "에이전트가 고른 곡은 스킵률이 높은가"를 나중에 측정할 수 있다.

### D. 외부 시스템

| # | 제공하는 것 | 경로 |

## 3. 화면 목록

**입력 방식은 `03-입력-설계.md` 참조.** 자연어가 기본이고, `/` 명령이 화면을 전환한다.

### S2. 묘비 — 죽은 곡

**액터:** 취향 관리자 · **기능:** B3~B6 · **진입:** `/graveyard [기준]` (기본 `never`)

미재생 곡 목록. 곡별 `마지막 재생일`, `누적 재생 횟수`를 보여주고
**되살리기 / 정리 / 비슷한 신곡 찾기** 세 행동을 제공한다.

### S3. 라이브러리 진단

**액터:** 취향 관리자 · **기능:** B1, B2 · **진입:** `/diagnose`

전체 곡 수, 최근 1년 재생률, 한 번도 재생하지 않은 곡 수와 비율, 마지막 동기화 시각.
**이 화면이 서비스의 문제 정의를 사용자 본인의 데이터로 증명한다.**

### S4. 취향 규칙

**액터:** 취향 관리자 · **기능:** B7, B8 · **진입:** `/rules`

스킵·완청 이력에서 도출된 규칙 목록.
예) *"3초 내 스킵 12회 — 새벽 시간대에 가사 있는 곡을 회피"*
각 규칙은 근거가 된 반응 횟수를 함께 표시하고, 사용자가 끄거나 고칠 수 있다.

### S5. 인식 결과 (Shazam)

**액터:** 청취자 · **기능:** A9, A10 · **진입:** `/shazam`

```
┌──────────────────────────────────────────────────────┐
│ 인식 결과                                             │
├──────────────────────────────────────────────────────┤
│  Tourner Dans Le Vide — Indila                        │
│  2014 · Pop · ISRC FR1PY1400070                       │
│                                                       │
│  ⚠  이미 라이브러리에 있습니다                        │
│     추가한 날 2026-07-30 · 재생 0회                   │
│     ★ 담아둔 뒤 한 번도 재생한 적 없음                 │
├──────────────────────────────────────────────────────┤
│  [지금 큐에 넣기]   [비슷한 곡으로 큐 짜기]           │
└──────────────────────────────────────────────────────┘
```

라이브러리에 **없으면** 대신 `[라이브러리에 추가]` 를 제공한다.
이 두 갈래가 F11의 전부이며, 서비스의 주장을 사용자가 직접 확인하는 지점이다.

### S6. 예외 · 오류 상태

**모든 화면에 걸쳐 나타나는 상태.** 별도 화면으로 명시해 누락을 막는다.

| # | 상황 | 화면 동작 |
|---|---|---|
| E1 | macOS 자동화 권한 거부 | 권한 안내 + 시스템 설정 열기 |
| E2 | Music.app 미실행 | 실행 유도, 확인 후 자동 재시도 |
| E3 | 라이브러리 미동기화 / 동기화 중 | 진행률 표시, 부분 데이터 경고 |
| E4 | 큐 생성 실패 (모델 오류·타임아웃) | 원인 표시 + 재시도 |
| E5 | 조건에 맞는 곡 없음 | 조건 완화 제안 |
| E6 | 곡이 로컬에 없음 (iCloud 미다운로드) | 해당 곡 건너뛰고 사유 표시 |
| E7 | Apple Music API 인증 만료 / 네트워크 끊김 | 카탈로그 기능만 비활성, 로컬 재생은 유지 |
| E8 | 재편성 중 사용자 조작 충돌 | 진행 중인 재편성 취소 후 재시도 |
| E9 | **마이크 권한 거부** | Shazam 기능만 비활성, 안내 표시 |
| E10 | **인식 실패 (매칭 없음)** | 재시도 안내. 소음·짧은 구간 가능성 표시 |

## 5. D2에서 이어서 할 것

1. S1~S6 전체 와이어프레임 (터미널 스크린 캡처 형태)
2. 화면의 **모든 표시 필드** 열거 → ERD 컬럼 도출 → `-DB.dbml`
3. 화면 행동별 필요 API 도출 → `-API.yml`
4. **추적 매트릭스**: `화면·필드 → 엔드포인트·응답필드 → 테이블·컬럼`

### 예상 엔티티 (D2에서 확정)

확정본은 `db/schema.dbml`, 도출 근거는 `docs/06-화면-필드.md`.

```
app_user ─1:N─ track ─N:1─ artist          track ─N:1─ album ─N:1─ artist
                 ├─M:N─ tag       (track_tag,      confidence 보유)
                 ├─M:N─ playlist  (playlist_track, position 보유)
                 ├─1:N─ queue_item ─N:1─ listening_session ─1:N─ session_turn
                 │          └─1:N─ reaction              queue_item ─N:1─ session_turn
                 └─0:1─ recognition   (F11, 미매칭 시 matched_track_id NULL)
taste_rule                                   sync_run
```

**15개 테이블 · M:N 2개 · 1:N 체인 2단.** 각각이 F1~F11 중 하나 이상에서 도출된다.
`session_turn` 은 자연어 요청 한 건을 담는 비동기 잡이며 API 의 `Turn` 과 1:1 대응한다.
