서비스의 문제가 데이터에서는 한 컬럼의 NULL 이다
play_count = 0 AND last_played_at IS NULL
— Never played 화면 전체가 이 조건이고, 재생 화면의 never played 경고도 같은 조건이다. 그래서 인덱스를 걸었다.
사용자 테이블이 없다
로그인 화면이 없기 때문이다. 한 사람의 기기에서 도는 로컬 데몬이고, 관문은 로그인이 아니라 macOS 자동화 권한이다.
저장하지 않기로 한 것
재생 위치 · 섞기 · 반복 · 볼륨 — 사용자가 Music.app 에서 직접 바꾼다.
앨범 커버 · 가사 — 우리 것이 아니다.
세션 누적 토큰 · 비용 — turn 을 합치면 나온다.
어긋난 값은 없는 값보다 나쁘다.
play 는 왜 끝났는지를 적는다
Music.app 은 스킵 횟수만 센다 — finished · skipped · removed · replaced 가 그 안에 뒤섞여 있다. 해석은 적지 않는다.
되돌릴 수 있는 해석만 저장한다
turn.context 는 이 설계에서 유일하게 저장하는 해석이다. 원문(prompt)이 그대로 남으므로 분류가 틀리면 지난 것을 다시 나눌 수 있다.

관계종류왜

track → queue_item1 : N
turn → queue_item1 : NFK NULL — 사람이 넣은 곡

track → play1 : N같은 곡을 여러 번 듣는다
queue_item → play1 : NFK NULL — 큐 밖의 재생
