## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | **Crate** |
| 한 줄 정의 | **내가 이미 가진 음악을 자연어로 파고, 왜 골랐는지 말해주고, 스킵하면 배우는 터미널 뮤직 플레이어** |
| 타겟 사용자 | 수년간 라이브러리를 모아온 Apple Music 구독자 — 특히 터미널에 상주하는 개발자 |
| 형태 | macOS 터미널 UI(TUI) 클라이언트 + 큐레이션 서버 |
| 없애려는 것 | **"3,000곡이 있는데 늘 듣던 200곡만 듣는다"** |

이름의 의미: **crate digging** — DJ가 레코드 상자를 뒤져 잊힌 판을 찾아내는 행위.

## 2. 문제 정의

### 현황 — 라이브러리의 대부분은 죽어 있다

구독료를 내고 수년간 곡을 모은다. 그런데 실제 재생은 극소수에 집중된다.

Music.app은 곡마다 `played count`(재생 횟수)와 `last played date`(마지막 재생일)를
갖고 있다. 이 두 값을 집계하면 다음이 즉시 드러난다.

```
라이브러리          3,240 곡
최근 1년 재생        187 곡  (5.8%)
3년 이상 무재생    1,904 곡  (58.8%)
```

> **이 수치는 주장이 아니라 사용자 본인의 라이브러리에서 계산된 값이다.**
> Crate의 "진단" 화면이 첫 실행 시 이 숫자를 보여주는 것으로 문제 정의를 대신한다.

곡을 모으는 행위는 계속되는데, **모은 것이 다시 재생되는 경로가 없다.**
라이브러리는 저장소일 뿐 순환하지 않는다.

### 원인

**① 탐색의 언어가 어긋난다**

| 앱이 이해하는 질문 | 사용자가 실제로 하는 질문 |
|---|---|
| "Radiohead" | "새벽에 코딩할 때 듣기 좋은 거" |
| "2019년" | "그때 그 여름에 계속 듣던 그거" |
| "재즈" | "지금은 가사가 있으면 방해돼" |

앱의 검색은 **이름**으로 찾는다. 사용자가 원하는 것은 **상태**다.
곡 제목을 기억하지 못하면 그 곡은 존재하지 않는 것과 같다.

스마트 플레이리스트가 이 간극을 메우도록 설계돼 있지만, 조건으로 쓸 수 있는 것은
장르·연도·별점 같은 **필드**뿐이다. "새벽에 듣기 좋은"은 어떤 필드에도 없다.

**② 추천이 바깥을 향한다**

자동재생과 추천은 카탈로그에서 **새 곡**을 가져온다. 서비스 입장에서는 합리적이다.
하지만 그 결과 내가 모은 것은 갱신되지 않는다.

```
       추천 알고리즘
            ↓
  [ 카탈로그 ] ──→ 새 곡 ──→ 재생
  [ 내 라이브러리 ] ·········· (건드려지지 않음)
```

**듣는 경로가 바깥으로만 나 있어서, 안쪽은 시간이 갈수록 두꺼워지고 조용해진다.**

### 배경 — 기존 도구로 안 되는 이유

| 도구 | 하는 일 | 못 하는 일 |
|---|---|---|
| Apple Music 자동재생 | 다음 곡을 이어 튼다 | **라이브러리 밖으로 나간다.** 내가 모은 것은 그대로 죽음 |
| 스마트 플레이리스트 | 규칙 기반 자동 갱신 | 필드 조건만 표현 가능. **"지금 기분"을 규칙으로 쓸 수 없음** |
| 수동 플레이리스트 | 정확하다 | 만드는 것이 노동. **만든 순간 화석이 됨** |
| 일반 음악 추천 AI | 취향을 학습한다 | 대상이 카탈로그다. 내 라이브러리를 모르고, **왜 골랐는지 설명하지 않음** |

## 3. 핵심 가치 3가지

| # | 가치 | 뜻 |
|---|---|---|
| ① | **안에서 고른다** | 추천의 후보 집합이 카탈로그가 아니라 **내 라이브러리**다 |
| ② | **이유를 말한다** | 고른 곡마다 한 줄 근거가 붙는다. 근거 없는 선택은 신뢰되지 않는다 |
| ③ | **거절이 학습된다** | 스킵은 버려지지 않는다. 다음 선택과 취향 규칙으로 남는다 |

## 4. 주요 기능 — 문제와의 연결

**모든 기능은 위 원인 중 하나에 대응한다.** 대응하지 않는 기능은 넣지 않는다.

| # | 기능 | 해결하는 것 |
|---|---|---|
| **F1** | 자연어로 재생 큐를 만든다 | 원인 ① — 상태의 언어로 라이브러리를 검색 |
| **F2** | 곡마다 선정 근거를 한 줄로 제시한다 | 신뢰 — 근거 없는 추천은 검증 불가 |
| **F3** | 큐를 되물어 그 자리에서 재편성한다 | 원인 ① — 한 번에 못 맞춘 것을 대화로 좁힘 |
| **F4** | 스킵·완청·좋아요를 반응으로 기록한다 | 가치 ③ — 거절을 데이터로 |
| **F5** | 반응에서 취향 규칙을 도출하고 사용자가 관리한다 | 가치 ③ — 학습을 사용자가 볼 수 있게 |
| **F6** | 라이브러리 재생률을 진단한다 | 현황 — 문제를 수치로 증명 |
| **F7** | 장기 미재생 곡(묘비)을 훑고 되살리거나 정리한다 | 원인 ② — 죽은 곡에 재생 경로를 만듦 |
| **F8** | 죽은 곡을 실마리로 카탈로그의 유사 신곡을 탐색한다 | 원인 ② — 바깥으로 나가되 **안쪽을 출발점으로** |
| **F9** | 마음에 든 큐를 Apple Music 플레이리스트로 저장한다 | 결과를 앱 생태계에 되돌려 놓음 |

## 5. 시스템 구성

TUI는 얇은 클라이언트이고, 큐레이션과 이력은 서버에 있다.
세션 재개·반응 누적·취향 규칙이 기기와 무관하게 유지되어야 하기 때문이다.

```
┌────────────────┐   HTTPS/JSON   ┌──────────────────┐
│  Crate TUI     │ ─────────────→ │  Crate Server    │
│  (터미널)      │ ←───────────── │  큐레이션 · 이력  │
└───────┬────────┘                └────────┬─────────┘
        │ AppleScript                      │ Apple Music API
        ↓                                  ↓
  ┌───────────┐                    ┌──────────────┐
  │ Music.app │                    │  카탈로그     │
  │ 로컬 재생 │                    │  (유사곡 탐색)│
  └───────────┘                    └──────────────┘
```

| 경계 | 담당 |
|---|---|
| TUI | 화면 렌더링, 키 입력, **로컬 Music.app 재생 제어** |
| 서버 | 라이브러리 색인, 큐 생성(LLM), 근거 생성, 반응 누적, 취향 규칙, 카탈로그 조회 |

## 6. 범위에서 제외하는 것

**의도적 제외이며, `고려사항` 섹션에 근거와 함께 명시한다.**

| 제외 | 이유 |
|---|---|
| 음성 입력 / 실시간 STT | 입력은 텍스트로 충분. 범위 과대 |
| 팀 · 공유 · 소셜 기능 | 1인용 도구로 정의됨 |
| 벡터 DB · 임베딩 파이프라인 | 라이브러리 규모(수천 곡)에서는 메타데이터 질의로 충분 |
| 음원 파일 직접 재생 | 재생은 Music.app에 위임 (DRM·코덱 문제 회피) |
| 모바일 · 웹 클라이언트 | 클라이언트는 macOS TUI 하나 |
| 곡 파일 삭제 | 묘비 "정리"는 **제외 표시**까지. 원본은 건드리지 않음 |
