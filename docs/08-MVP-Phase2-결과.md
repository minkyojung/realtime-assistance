## 2. 설계가 의도대로 작동한 지점

### ① 물음표 신호가 한국어 어미 문제를 대신 해결

`"~어려운데요"`, `"~할 것 같은데요"` 둘 다 종결어미가 모호하지만 카드가 뜨지 않았다.
`KoSEnd` 연구가 지적한 한국어 종결어미 모호성을 STT의 문장부호 예측이 흡수한다.
(근거: `docs/07-한국어-STT-스모크테스트.md`)

### ② intent=when 이 확정 답변을 차단

`"언제 지원되나요"`는 **규칙 검색 자체를 건너뛰고** 🔴로 갔다.
스파이크 1에서 T0를 폐기하고 도입한 의도 축 분리가 여기서 값을 한다.
미확정 로드맵이 고객에게 나갈 경로가 코드상 존재하지 않는다.

### ③ 조건부 규칙이 세션 컨텍스트를 실제로 검사

온프레미스 규칙은 `direct`로 등록돼 있으나 `nda_signed=false`라 🟡로 내려갔고,
경고 문구까지 함께 표시됐다.

### ④ 실패가 기록으로 남았다

공백 2건 생성. 이것이 화면 2(지식 공백 큐)의 입력이며 3막 루프의 출발점이다.

## 3. 지연 실측

| 단계 | 평균 | 최대 | 예산 |
|---|---|---|---|
| 판정 (검색) | **224ms** | 626ms | 1,050ms |
| STT 450ms 가산 | **674ms** | 1,076ms | **1,500ms** |
| 제안 문구 첫 토큰 | 1,522ms | 2,226ms | (뒤따라옴) |

### 도중에 설계를 바꾼 지점

최초 구현에서는 목표를 크게 초과했다.

```
수정 전   판정 725ms · headline 2,841ms · STT 포함 3,291ms   ← 목표의 2배
수정 후   판정 224ms · headline 224ms  · STT 포함   674ms   ← 목표 충족
```

**원인 1 — 임베딩 중복 호출**
규칙 검색과 근거 검색이 각각 임베딩을 호출하고 있었다. 병렬이어도 호출 자체가 비싸다.
→ 벡터를 한 번만 계산해 두 검색이 공유.

**원인 2 — headline 을 생성 모델로 만들고 있었다**
설계는 "headline 우선 스트리밍"이었으나, 실측 TTFT가 3초였다.
스트리밍을 해도 모델이 추론을 끝내야 첫 토큰이 나온다.
그런데 결과물은 질문 요약에 불과했다 (`"SOC 2 인증도 받으셨나요?"` → `"SOC 2 확인 요청"`).

→ **headline 을 모델 경로에서 제거한다.**

| 상황 | headline |
|---|---|
| 규칙 매칭됨 | 승인된 `headline_template` 그대로 |
| 규칙 없음 | `확정 답변 없음 · {질문}` |
| `intent=when` | `일정 확인 필요 · {질문}` |

모델은 실제로 입에 낼 문구(`script`) 생성에만 사용하고, 그것은 뒤따라 스트리밍된다.

**결과적으로 UX가 개선됐다.** 사용자는 0.3초에 색과 요약으로 상황을 파악하고,
문구는 읽기 시작할 때쯤 도착한다.

## 4. 구현 범위

| 계층 | 구현 |
|---|---|
| 세션 | `POST /api/sessions`, `GET/PATCH/POST` 컨텍스트·종료 |
| 실시간 | `GET /api/sessions/{id}/stream` (SSE) |
| 파이프라인 | 발화 저장 → 감지 → 정규화 → 의도 → 판정 → 생성 → 공백 |
| 화면 | `/panel` 대화형 레이아웃 |
| 입력 | `ScriptedSource` (오디오 미사용) |

### 설계 문서와 다른 점

| 항목 | 설계 | MVP | 이유 |
|---|---|---|---|
| 실시간 채널 | WebSocket | **SSE** | 단방향 푸시만 필요. 이벤트 종류·순서 동일 |
| 오디오 입력 | 2트랙 캡처 | **ScriptedSource** | `AudioSource` 인터페이스 뒤. 파이프라인 동일 |
| 질문 감지 2차 | 소형모델 | **규칙만** | 1차 규칙 정확도 15/15로 충분. 필요 시 추가 |

세 가지 모두 파이프라인 이후 단계에 영향을 주지 않는다.
