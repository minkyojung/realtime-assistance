# §3. UI 흐름 (와이어프레임)

> PDF 3장. 배점이 가장 큰 섹션이다.
> **와이어프레임 캡처는 반드시 PDF 파일 안에 있어야 한다** — 외부 링크 불가.

---

## 3-1. 먼저 알아야 할 것 — 이 서비스는 화면이 하나다

일반적인 웹 서비스는 로그인 → 목록 → 상세로 **페이지가 이동한다.**
이 서비스는 이동하지 않는다. **화면은 하나이고, 그 안의 목록 패널이
무엇을 담을지만 바뀐다.**

터미널 앱이기 때문이다. 창을 새로 띄울 수 없고, 화면을 통째로 갈아치우면
지금 무엇이 재생 중인지가 사라진다. **재생은 어느 화면에 있든 끊기면 안 되는
유일한 것**이므로, 그것을 늘 같은 자리에 두고 나머지를 바꾼다.

```
┌──────────────────────────────────────────┐
│                                          │
│   ① 지금 재생        커버 · 제목 · 진행바 · 가사   │  ← 절대 안 바뀐다
│                                          │
│  ────────────────────────────────────────│
│                                          │
│   ② 목록 패널                              │  ← 여기만 갈아끼워진다
│      Recent / Artists / Albums / Songs    │
│      / Playlists / Queue / Unplayed       │
│      / Catalog                            │
│                                          │
│  ────────────────────────────────────────│
│   ③ 대화 띠      내 말 · 답 · 곡별 근거 · 비용    │  ← 물어봤을 때만
│   ④ 입력창      [ 여기에 친다 ]               │  ← 늘 같은 자리
│   ⑤ 팔레트      / 를 치면 여기 펼쳐진다          │  ← 눌렀을 때만
│   ⑥ 상태줄      지금 어디 · 큐 N · 토큰 · 비용     │  ← 늘 같은 자리
└──────────────────────────────────────────┘
```

**이 구조를 먼저 설명하지 않으면 뒤의 캡처 8장이 전부 비슷해 보인다.**
바뀌는 것은 ②뿐이고, 나머지는 어느 캡처에서나 같은 자리에 있다.

## 3-2. 화면 목록 — 8장

| # | 화면 | 무엇을 보여주는가 | 관련 기능 |
|---|---|---|---|
| W1 | 홈 (스플래시) | 무엇에 붙어 있고 무엇이 막혀 있는가 | 진입 · 관문 |
| W2 | 메인 — Recently Added | 최근 담은 곡 | 둘러보기 |
| W3 | 메인 — Artists 파고들기 | 아티스트 묶음 → 그 아티스트의 곡 | 둘러보기 |
| W4 | 메인 — Queue | 다음에 틀 곡 · **선정 근거** | 큐 조작 · AI |
| W5 | 메인 — Unplayed | **한 번도 안 튼 곡** | 이 서비스의 문제 정의 그 자체 |
| W6 | 메인 — Catalog | Apple Music 검색 · 담기 | 라이브러리 넓히기 |
| W7 | 명령 팔레트 | 갈 수 있는 곳과 할 수 있는 일 전부 | 탐색 |
| W8 | 관문 · 오류 | 막혔을 때 무엇을 하면 되는가 | 예외 |

## 3-3. 흐름도

화면 이동이 아니라 **구역 전환과 입력 모드 전환**이다.

```
                    ┌──────────┐
       실행 ───────▶ │  W1 홈   │
                    └────┬─────┘
                         │ enter
                         ▼
      ┌────────────────────────────────────────┐
      │            메인 (W2~W6)                 │
      │                                        │
      │   tab ─────▶ 다음 구역으로 순환           │
      │   /  ─────▶ 먼 구역으로 곧장 (W7 팔레트)   │
      │   ↑↓ ─────▶ 목록 이동                    │
      │   enter ──▶ 고른 것부터 재생 · 묶음이면 파고듦 │
      │   shift+↓ ▶ 재생 / 일시정지              │
      │   shift+←→ 이전 / 다음 곡                │
      │                                        │
      │   문장 입력 ─▶ AI 큐 요청 (비동기)         │
      │   shift+tab ▶ 입력 모드 왕복 (묻기 ↔ 찾기)  │
      │   ctrl+j ──▶ 대화 띠 접기 / 펴기          │
      └───────────────┬────────────────────────┘
                      │ esc — 한 단계씩 물러난다
                      ▼
        진행 중인 요청 취소 → 파고들기 해제 → 홈 → 종료
```

**`esc` 는 사슬이다.** 물러날 곳이 있으면 거기까지만 가고, 없으면 다음 칸으로
넘어간다. 새로 배울 키가 없다는 것이 이 설계의 요점이다.

## 3-4. 화면별 구성 요소와 동작

### W1. 홈

| 구성 요소 | 내용 | 데이터 출처 |
|---|---|---|
| 워드마크 | 서비스 이름 | 고정 |
| Sources | Music.app · Apple Music · LRCLIB · AI 각각의 연결 상태 | `GET /status` |
| Library | 보유 곡 수 · 플레이리스트 수 | `GET /status` |
| Commands | 칠 수 있는 명령 이름과 총 개수 | 고정 |
| 관문 사유 | 권한이 없거나 Music.app 이 안 떠 있으면 그 사실 | `GET /status` |

**동작:** `enter` 하나뿐이다. **이 화면에서만 입력창과 상태줄이 접힌다** —
칠 것이 없는 화면에 입력창을 그려 두면, 쳐 봐야 아무 일도 안 일어나는
입력창은 고장으로 보인다.

### W2·W3. 메인 — 둘러보기

| 구성 요소 | 내용 | 데이터 출처 |
|---|---|---|
| 지금 재생 | 커버 · 제목 · 아티스트 · 앨범 · 진행바 · 가사 | `GET /playback` · `/playback/artwork` · `/playback/lyrics` |
| 곡 이력 | 가사가 없으면 그 자리에 — 장르 · 연도 · 추가일 · 마지막 재생일 · 재생 횟수 | `GET /playback` |
| 목록 행 | 제목 · 아티스트 · 재생 횟수 · 길이 | `GET /tracks` |
| 묶음 행 | 아티스트명 / 앨범명 · 곡 수 · 누적 재생 수 | `GET /artists` · `GET /albums` |

**동작:** `↑↓` 로 고르고 `enter` 로 재생한다. 묶음 행에서 `enter` 를 누르면
파고들고, `esc` 로 나온다.

**반응형:** 창이 좁아지면 칸이 순서대로 사라진다 — 재생 횟수 → 아티스트 →
길이. 제목은 절대 버리지 않는다. 세로가 짧으면 앨범 커버 대신 한 줄짜리
재생 바가 된다.

### W4. 메인 — Queue

| 구성 요소 | 내용 | 데이터 출처 |
|---|---|---|
| 큐 순번 | 몇 번째로 틀 곡인가 | `GET /queue` → `items[].position` |
| **선정 근거** | AI 가 이 곡을 왜 골랐는지 한 줄 | `items[].reason` |
| 큐 요약 | 곡 수 · 총 길이 (상태줄) | `trackCount` · `totalDurationMs` |

**동작:** `/next` 지금 곡 뒤에 넣기 · `/later` 맨 뒤에 넣기 · `/remove` 빼기 ·
`/up` `/down` 순서 바꾸기 · `/clear` 비우기 · `/save <이름>` 플레이리스트로 저장.

**중요:** 큐를 손대도 **재생이 끊기지 않는다.** 지금 곡은 그대로 가고 뒤만 바뀐다.

### W5. 메인 — Unplayed

| 구성 요소 | 내용 | 데이터 출처 |
|---|---|---|
| 곡 목록 | 담은 뒤 **한 번도 재생하지 않은 곡만** | `GET /tracks?unplayed=true` |
| 추가일 | 언제 담았는지 | `items[].addedAt` |

**동작:** 고르면 그 자리에서 재생하거나 큐에 넣는다.

**설계 근거:** `track.last_played_at` 이 `NULL` 인 것 하나로 이 구역이 만들어진다.
같은 값이 재생 화면에서는 `never played` 경고로 나타난다. **컬럼 하나가 화면
두 곳을 지탱한다.**

### W6. 메인 — Catalog

| 구성 요소 | 내용 | 데이터 출처 |
|---|---|---|
| 검색 결과 | 제목 · 아티스트 | `GET /catalog/tracks?q=` |
| **보유 표시** | `✓` 이미 있음 · `+` 없음 · `⋯` 담는 중 | `items[].inLibrary` |

**동작:** `enter` 로 라이브러리에 담는다. 표시가 `+` → `⋯` → `✓` 로 바뀐다.

**조건부 화면:** Apple Music 설정(`/setup`)이 없으면 **이 구역 자체가 생기지 않는다.**
쓸 수 없는 곳으로 `tab` 이 가면 안 되기 때문이다.

### W7. 명령 팔레트

`/` 를 치면 입력창 아래에 펼쳐진다. **사이드바가 없는 이유가 이것이다** —
"갈 수 있는 곳"을 화면에 상시로 둘 필요가 없고, 필요한 것은 "지금 어디인지"
뿐이며 그것은 상태줄이 말한다.

호스트의 명령과 앱의 명령이 **하나의 목록으로** 합쳐져 보인다.

### W8. 관문 · 오류

| 상황 | 화면이 하는 말 | 사용자가 할 것 | 응답 |
|---|---|---|---|
| 자동화 권한 거부 | `PERMISSION` Allow Terminal to control Music | `ctrl+g` 로 시스템 설정 열기 | `403 AUTOMATION_PERMISSION_DENIED` |
| Music.app 미실행 | `MUSIC APP` Music is not running | `open -a Music` | `503 MUSIC_APP_NOT_RUNNING` |
| AI 꺼짐 | `AI is off` | `/ai <key>` | `409 AI_NOT_CONFIGURED` |
| 카탈로그 미설정 | 구역이 생기지 않음 | `/setup <team ID>` | `409 CATALOG_NOT_CONFIGURED` |
| 가사 없음 | 그 자리에 곡 이력을 그림 | 없음 — 정상이다 | `404 LYRICS_NOT_FOUND` |
| 동기화 중 | 상태줄에 `⟳ syncing` | 기다림 | `409 SYNC_IN_PROGRESS` |
| 선곡 실패 | 대화 띠에 실패 문장 | 다시 물어봄 | `turn.errorCode` |

**원칙 — 화면은 "왜 안 되는지"가 아니라 "무엇을 하면 되는지"를 말한다.**
모든 오류 응답에 `hint` 필드가 있는 이유다.

## 3-5. 비동기 요청의 화면 처리

자연어 요청은 선곡에 초 단위가 걸린다. 화면이 멈추면 안 되므로 이렇게 흐른다.

```
사용자가 문장을 친다
   │
   ├─▶ POST /turns ────────────▶ 202 즉시 응답 (아직 답 없음)
   │                                  │
   │   대화 띠에 내 말이 뜨고,            │
   │   답이 앉을 자리에 스피너가 앉는다      │
   │                                  │
   │   ◀── GET /turns/{id} 폴링 ────────┘
   │
   ├─ status=done ──▶ 답 · 곡별 근거 · 토큰 · 비용이 대화 띠에 그려지고
   │                   큐가 갱신된다
   ├─ status=failed ▶ 실패 문장이 대화 띠에 남는다. 재생은 계속된다
   └─ esc ─────────▶ POST /turns/{id}/cancel → status=canceled
```

**스피너가 답의 자리에 그대로 앉는 것이 요점이다.** 기다릴 때와 답이 왔을 때
줄 자리가 다르면, 답이 도착하는 순간 화면이 한 번 튄다.
