# Relay — 액터별 기능 요구사항

> 산출물 ②. PDF 2장 "시스템 액터 정의" 재료.
> 모든 기능은 화면에 배치되고, 화면의 모든 요소는 기능에서 나온다.

---

## 액터 3명

| 액터 | 누구인가 | 주 화면 | 루프 위치 |
|---|---|---|---|
| **발화자** | 고객을 만나는 세일즈·PM | 실시간 어시스트 패널 | 1막 (질문 발생) |
| **정보 승인자** | 개발팀·PM | 지식 공백 큐 | 2막 (답 채우기) |
| **지식 관리자** | 운영 담당 | 답변 규칙 관리 | 3막 (유지·갱신) |

> 한 사람이 여러 액터를 겸할 수 있다. 권한 분리는 과제 범위 밖(Security Schemes 제외).

## A. 발화자 — 실시간 어시스트 패널

| # | 기능 | 화면 구역 | 비고 |
|---|---|---|---|
| A1 | 세션을 시작한다 | 세션 헤더 | 상대 조직명, 도메인, 컨텍스트 입력 |
| A2 | 세션 컨텍스트를 수정한다 | 세션 헤더 | 대화 중 NDA 체결 등 상태 변경 |
| A3 | 오디오 캡처를 켜고 끈다 | 세션 헤더 | 마이크/시스템 오디오 2트랙 |
| A4 | 대화 전사를 본다 | 전사 스트림 | 화자 구분 표시 |
| A5 | **감지된 질문의 판정 카드를 본다** | 판정 카드 | **핵심 기능** |
| A6 | 할 말 문구를 본다 | 판정 카드 | `suggested_script` |
| A7 | 근거를 펼쳐 본다 | 판정 카드 (접힘) | GitHub 원문 링크 |
| A8 | **답변이 틀렸다고 신고한다** | 판정 카드 | → 공백 재생성 |
| A9 | 지난 질문 목록을 훑는다 | 질문 히스토리 | 세션 내 누적 |
| A10 | 세션을 종료한다 | 세션 헤더 | 미해소 공백이 큐로 확정 |

### A5 판정 결과 3종

| 표시 | `response_mode` | 언제 | 사용자가 할 일 |
|---|---|---|---|
| 🟢 초록 | `direct` | 확정 답변 존재, 컨텍스트 충족 | 문구 그대로 말한다 |
| 🟡 노랑 | `conditional` | 확정 답변 존재하나 조건 미충족 | 조건부 문구를 말한다 |
| 🔴 빨강 | `escalate` | 답변 없음 / `intent=when` | 확인 후 회신을 말한다. 공백 생성됨 |

## B. 정보 승인자 — 지식 공백 큐

| # | 기능 | 화면 구역 | 비고 |
|---|---|---|---|
| B1 | 미해소 공백 목록을 본다 | 큐 리스트 | **발생 빈도순 정렬** |
| B2 | 공백을 필터링한다 | 큐 필터 | 사유별 / 도메인별 / 기간별 |
| B3 | 공백 상세를 본다 | 상세 패널 | 원문 발화, 정규화 질문, 발생 이력 |
| B4 | 관련 GitHub 근거를 확인한다 | 상세 패널 | 시스템이 찾아둔 후보 청크 |
| B5 | **답변 규칙을 작성한다** | 작성 폼 | **핵심 기능** |
| B6 | 공개 등급을 지정한다 | 작성 폼 | `public` / `nda` / `internal` |
| B7 | 조건과 조건별 문구를 넣는다 | 작성 폼 | 조건 충족/미충족 각각 |
| B8 | 유효 기간을 설정한다 | 작성 폼 | `valid_until` |
| B9 | 공백을 규칙으로 해소한다 | 작성 폼 | **양방향 FK 연결 생성** |
| B10 | 답변 불가로 기각한다 | 상세 패널 | 사유 기록 |

### B1 정렬이 빈도순인 이유

전통적 사내 위키는 "무엇을 써야 할지 모른다"는 이유로 비어 있다.
Relay는 **대화가 우선순위를 정해준다.** "이 12개에 답해주세요, 각각 3회·5회 물어봤습니다."

## 기능 ↔ 화면 매핑 검증

| 화면 | 담당 기능 | 개수 |
|---|---|---|
| 실시간 어시스트 패널 | A1~A10 | 10 |
| 지식 공백 큐 | B1~B10 | 10 |
| 답변 규칙 관리 | C1~C9 | 9 |

**모든 기능이 화면에 배치됐고, 배치되지 않은 기능은 없다.**

---

## 루프 연결 (기능 간 인과)

```
A5 판정 실패 (🔴)
   └→ 공백 생성
        └→ B1 큐에 노출 (빈도순)
             └→ B5 규칙 작성
                  └→ B9 해소 + 양방향 FK
                       └→ A5 다음번 즉답 (🟢)
                            └→ C8 커버리지 지표 상승
```

**A8(답변 틀림 신고)도 같은 경로로 들어간다.** 공백 생성 트리거가 2개가 된다.

| 트리거 | 사유(`reason`) |
|---|---|
| 매칭 실패 | `no_rule` |
| 지식 자체 없음 | `no_knowledge` |
| 조건 미충족 | `condition_unmet` |
| `intent=when` 차단 | `unconfirmed_timeline` |
| **사용자 신고 (A8)** | **`user_rejected`** |

## 범위 밖 (기획서에 명시)

| 제외 | 이유 |
|---|---|
| 로그인·권한 관리 | 과제 Security Schemes 제외 항목 |
| 고객 화면 노출 | 담당자 본인 전용 도구 |
| 자동 발송 | 문구 제안만. 말하는 주체는 사람 |
| CRM 연동 | 세션 컨텍스트는 수동 입력 |
| 화자 N명 구분 | `participant` 테이블로 확장만 가능하게 |
