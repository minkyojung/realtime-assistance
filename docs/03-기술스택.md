## 스택

| 계층 | 기술 | 역할 |
|---|---|---|
| 데스크톱 클라이언트 | Electron + React + TypeScript | 마이크·시스템 오디오 2트랙 로컬 캡처, 실시간 어시스트 패널 |
| 웹 콘솔 | Next.js (App Router) + TypeScript | 지식 공백 큐, 답변 규칙 관리 |
| 백엔드 | Node.js + Fastify (TypeScript) | REST API + WebSocket 스트리밍 |
| DB | PostgreSQL + pgvector | 관계형 + 벡터 단일 DB |
| STT | OpenAI `gpt-live-transcribe` | 트랙당 전사 세션 1개, `semantic_vad` 턴 감지 |
| 질문 감지 (2차) | OpenAI `gpt-5.6-luna` | Structured Outputs → `{is_question, normalized}` |
| 판정·문구 생성 | OpenAI `gpt-5.6-terra` | 스트리밍, headline 우선 |
| 임베딩 | OpenAI `text-embedding-3-small` (1536d) | 질문·지식 청크 벡터화 |
| 지식 인입 | GitHub Webhooks + REST 백필 | 이벤트 타입 → `audience_level` 강제 지정 |
| 배포 | Vercel (웹) / Fly.io (WS 서버) / Neon (DB) | — |

## 선택 근거

| 결정 | 이유 |
|---|---|
| 벡터DB 분리 안 함 (pgvector) | 지식 청크가 ERD 밖으로 나가면 화면↔API↔ERD 정합성이 깨짐 |
| 브라우저 아닌 Electron | macOS 시스템 오디오 루프백은 브라우저 불가. Tauri는 Rust로 직접 캡처 구현 필요 (Meetily 방식) → 3일 불가 |
| AI 계층 OpenAI 단일 벤더 | 키·SDK·청구·장애 지점 각 1개. 이 규모에서 모델 품질 차이 체감 없음 |
| STT = OpenAI | AssemblyAI·Deepgram Flux는 **한국어 스트리밍 미지원** (`01-설계-결정.md` 조사 결과 참조) |
| 전 계층 TypeScript | ML 학습 없음, 전부 API 호출 → 언어 분리 이득 없음 |

## MVP 착수 전 확인 사항

1. `gpt-live-transcribe` 한국어 1분 테스트 — 지원 확정 + **마이크→최종 transcript 지연 실측** (예산 표 150ms 근거 교체용)
2. 정확도 부족 시 리턴제로로 교체 — `AudioSource` 인터페이스 뒤라 파이프라인 변경 없음
