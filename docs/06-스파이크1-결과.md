# 스파이크 1 결과 — T0(즉답 캐시)는 성립하지 않는다

> 2026-09-08 실행. `spikes/spike1_t0.py`, 원자료 `spikes/out/spike1.json`
> **결론: 사전 합의대로 T0 폐기 → 2티어 + 의도 필터로 전환**
>
> ⚠️ 이 문서는 실측 기록이다. 같은 날 이뤄진 3단계 개편(`02`·`04`·`05`) 이전
> 용어를 일부 사용하지만, 측정값과 결론(임베딩 모델·의도 축 분리)은 그대로 유효하다.

---

## 1. 무엇을 검증했나

"임베딩이 같은 질문을 알아보는가"가 아니라

> **"같은 질문의 다른 표현"과 "비슷하지만 다른 질문" 사이에
> 임계값을 그을 틈이 있는가**

데이터셋은 `supabase/supabase` 실제 이슈·PR에 근거해 구성.

| 세트 | 수 | 설명 |
|---|---|---|
| 원형 질문 | 10 | Layer 2에 저장돼 있다고 가정 |
| 패러프레이즈 | 50 | 같은 질문의 실제 발화체 변형 |
| 하드 네거티브 | 15 | 어휘는 비슷하나 답이 다른 질문 |

---

## 2. 결과

| | 3-small | **3-large** |
|---|---|---|
| A 패러프레이즈→원형 (median) | 0.405 | 0.525 |
| **B 하드네거티브→최근접 (median)** | **0.615** | **0.647** |
| B 최댓값 | 0.915 | 0.859 |
| top1 정확도 | 66% | **86%** |
| **margin (minA − maxB)** | −0.762 | **−0.530** |
| 안전 임계값에서 T0 커버리지 | 0% | **0%** |

### 핵심 관찰 — 분포가 역전됐다

```
같은 질문끼리  median 0.53
다른 질문끼리  median 0.65   ← 더 높음
```

**다른 질문이 같은 질문보다 더 비슷하게 나온다.**
임계값을 어디에 그어도 고칠 수 없다.

---

## 3. 원인 — 임베딩은 의도가 아니라 어휘를 잰다

```
"Edge Functions 쓸 수 있나요"  vs  "Edge Functions 언제 지원되나요"  → 0.859
"SSO 로그인 지원하나요"        vs  "싱글사인온요"                    → 0.330
```

뜻이 정반대여도 어휘가 같으면 높고, 같은 뜻이어도 어휘가 다르면 낮다.

그리고 **0.859짜리 쌍이 우리 설계에서 가장 위험한 쌍**이다.

| 질문 | 근거 | audience_level |
|---|---|---|
| "쓸 수 있나요" | 머지된 PR | `public` |
| "언제 지원되나요" | 열린 마일스톤 | **`internal`** |

유사도만으로 즉답하면 **미확정 로드맵을 확정처럼 말하게 된다.**

### 정규화를 먼저 해도 안 고쳐진다

위 0.859 쌍은 이미 둘 다 정규화된 형태다.
A를 0.86까지 끌어올려도 그 지점에 B가 앉아 있다.

---

## 4. 단, 검색 자체는 멀쩡하다

**top1 정확도 86% (3-large).** 랭킹은 되는데 절대 임계값이 안 되는 것.

| | 되는가 |
|---|---|
| 후보를 좁히는 것 (검색) | ✅ |
| 임계값만 보고 LLM 없이 확정 (T0) | ❌ |

죽은 것은 **"LLM 없이 50ms에 확정"** 하나뿐.
T1·T2·2계층 지식·학습 루프는 전부 유지된다.

---

## 5. 업계 조사 — 알려진 근본 한계였다

### 진단

> 쿼리 토큰이 인코딩 과정에서 문서 토큰과 **직접 상호작용하지 않기 때문에**,
> 모델은 **의도 정합성이 아니라 주제 유사도만 측정한다.**
> 부정, 논리적 제약, 미묘한 형식 차이에 취약하다.  — ZeroEntropy

교과서 예시가 우리 케이스와 동일하다.

```
쿼리: "파산하지 않은 회사들"
문서: (A) 챕터11 파산 신청  (B) 사상 최대 이익
      → 임베딩은 구분하지 못함
```

`"않은"`을 못 읽는 것과 `"언제"`를 못 읽는 것은 같은 실패다.

### 표준 해법 4계층

```
① Query Understanding   자연어 → 구조화된 의도 신호
② Metadata Filtering    검색 전에 공간을 좁힘 (85~98% 축소)
③ Hybrid Search         BM25 + 벡터
④ Reranking             cross-encoder 재정렬
```

**① Query Understanding**
> 쿼리 이해층은 사람의 언어를 나머지 시스템이 실행할 수 있는 구조화된 의도
> 신호로 번역한다. **의도가 이 단계에서 잘못 해석되면 관련 문서는 애초에
> 후보군에 들어오지 못한다.**

구현 방식과 트레이드오프

| 방식 | 정확도 | 지연 | 평가 |
|---|---|---|---|
| 정규식/규칙 | 중 | **0ms** | 1차 필터 |
| BERT 파인튜닝 | 최고 | 낮음 | 프로덕션 최선 |
| LLM 제로샷 | 높음 | 높음 | **실시간엔 비쌈** |

> 권장: **빠른 정규식 매처를 먼저 쓰고, 실패 시 LLM 제로샷으로 폴백하는 2단 구조**

**④ Reranking 실측**

| 구현 | p50 |
|---|---|
| 경량 CPU, 문서 20건 | 80~120ms |
| Cohere Rerank 3.5 | 80~150ms |
| Voyage rerank-2.5-lite | **85ms** |

품질 (엔지니어링 질의 150건)

| 지표 | Dense만 | Hybrid | Hybrid+Rerank |
|---|---|---|---|
| Context Precision | 0.61 | 0.71 | **0.79** |
| Context Recall | 0.74 | **0.83** | 0.84 |
| Answer Relevancy | 0.78 | 0.81 | **0.87** |

→ recall은 hybrid가 올리고, **리랭커가 올리는 건 precision.**
"못 찾던 걸 찾아주는" 게 아니라 **"찾은 것 중 잘못된 걸 밀어내는"** 역할.
우리 문제(비슷하지만 다른 질문이 상위에 옴)에 정확히 맞는다.

### 시제 문제는 업계도 미해결

> 정책 문서가 "30일"에서 "60일"로 개정되면, 질문과 **두 버전 모두의 코사인
> 유사도가 거의 동일**하다. 시간 신호 없이는 검색기가 둘을 구분할 수 없다.

recency 가중 방식의 실측:
> 특정 데이터셋에 맞춰 튜닝했을 때만 정확도 1.00, **기본 설정에서는 0.00.**
> CVE 데이터에서 60%. **"실재하지만 제한적인 능력이지 해결된 문제가 아니다."**

**→ 시제를 검색 알고리즘으로 풀면 안 된다.** 튜닝에 극도로 민감하고
파라미터가 어긋나면 0점이 나온다. 로드맵 유출이 걸린 시스템에서 신뢰 불가.
**규칙으로 우회하는 것이 옳다.**

## 6. 채택 설계 — 질문을 (주제, 의도)로 쪼갠다

### 비유

```
"김치찌개 있어요?"      → 메뉴판 보면 됨      (즉답 가능)
"김치찌개 언제 나와요?"  → 주방에 물어봐야 함  (즉답 불가)
```

주제는 같은데 답을 가져올 곳이 다르다.

### 동작

**1단계 — 쪼갠다 (정규식, 0ms)**

| 질문 | 주제 | 의도 |
|---|---|---|
| "Edge Functions 쓸 수 있나요?" | edge-functions/self-host | `exists` |
| "Edge Functions 언제 되나요?" | edge-functions/self-host | **`when`** |

**2단계 — 의도가 갈 곳을 정한다**

| intent | 매칭 대상 | 결과 |
|---|---|---|
| `exists` / `status` | 확정 답변 (머지 PR·릴리즈) | 🟢 즉답 |
| **`when`** | **확정 답변 매칭 금지** | 🟡 승인 경로 |
| `price` | 승인된 규칙만 | 조건부 |
| `how` | 문서 안내 허용 | 🟢 |

**3단계 — 주제로만 검색** (유사도 0.86이든 무관. 이미 다른 서랍을 봄)

### 쿼리

```sql
SELECT * FROM response_rule
WHERE topic_embedding <-> :q < :threshold
  AND intent = :intent            -- ← 추가된 한 줄
  AND audience_level <= :level
```

`audience_level`과 **같은 층위**. 기존 구조에 컬럼 하나 추가.

### 왜 안전한가

```
❌ LLM에게 "시점 질문이니 조심해" 지시     → 모델 실수 시 유출
✅ 시점 질문엔 확정 답변이 검색되지 않음   → 모델이 실수해도 못 봄
```

원안 원칙 2의 확장이지 새 원칙이 아니다.

## 7. 수정된 티어 구조

| 티어 | 조건 | 처리 | 지연 |
|---|---|---|---|
| ~~T0~~ | ~~유사도 임계값~~ | **폐기** | — |
| **T1** | 규칙 히트 + intent 일치 | 소형모델이 문구 조정 | ~400ms |
| **T2** | 히트 없음 / `intent=when` | Layer 1 검색 + 생성 + `knowledge_gap` | ~1,500ms |

### 수정 지연 예산 (T2 최악)

| 단계 | 예산 |
|---|---|
| 턴 종료 감지 + STT | 450ms |
| intent 규칙 | **0ms** |
| 하이브리드 검색 (필터 적용) | 200ms |
| 리랭커 (선택) | +85ms |
| 생성 첫 토큰 | 500ms |
| **누적** | **~1,235ms** |

**리랭커를 넣어도 1.5초 안에 들어온다.** (스파이크 2에서 실측)

## 8. 확정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 임베딩 모델 | **`text-embedding-3-large`** | top1 66% → 86% |

## 10. 이 스파이크의 의미

```
가설:  임계값 하나로 즉답 캐시가 된다
실측:  안 된다 (margin −0.53)
```
