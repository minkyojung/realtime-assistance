# Relay — 화면 구역 · 필드 명세

> 산출물 ③-a. **ERD(DBML)와 API(YML)의 직접 입력.**
> 규칙: 여기 없는 필드는 ERD에도 API에도 없다. 여기 있는 필드는 반드시 둘 다에 있다.

범례 — **출처**: `테이블.컬럼` / `생성`(AI) / `계산`(집계)
범례 — **시점**: `초기`(화면 진입) / `푸시`(WebSocket) / `요청`(사용자 액션)

# 화면 1. 실시간 어시스트 패널

담당 액터: 발화자 (A1~A10)

```
┌─ ① 세션 헤더 ───────────────────────────┐
│ [Acme Corp ▾] discovery · NDA 미체결     │
│ 🔴 녹음 중 02:14        [컨텍스트][종료] │
├─ ② 판정 카드 (최신 질문) ────────────────┤
│ 🟢 바로 답변 가능                        │
│ Enterprise 플랜에서 온프레미스 지원       │
│ ─ 이렇게 말하세요 ─                      │
│ "Enterprise 플랜에서 지원합니다..."       │
│ ⚠ NDA 미체결 — 노드 수 언급 보류          │
│ ▸ 근거 3건        [👎 답변이 틀렸어요]    │
├─ ③ 질문 히스토리 ────────────────────────┤
│ 🟢 SSO 지원 여부           14:02         │
│ 🔴 Edge Functions 일정     13:58         │
├─ ④ 전사 스트림 ──────────────────────────┤
│ 고객  저희는 금융권이라...     13:58      │
│ 나    네, 그 부분은...         13:57      │
└─────────────────────────────────────────┘
```

## ① 세션 헤더

| 화면 요소 | 필드 | 타입 | 출처 | 시점 |
|---|---|---|---|---|
| 상대 조직명 | `counterpart_org` | string | `session.counterpart_org` | 초기 |
| 도메인 배지 | `domain` | enum(sales/recruiting) | `session.domain` | 초기 |
| 컨텍스트 요약 | `context` | jsonb | `session.context` | 초기 |
| 녹음 상태 | `is_capturing` | bool | 클라이언트 상태 | — |
| 경과 시간 | `started_at` | timestamp | `session.started_at` | 초기 |
| 세션 상태 | `status` | enum(active/ended) | `session.status` | 초기 |
| [컨텍스트] 버튼 | — | — | → `PATCH /sessions/{id}/context` | 요청 |
| [종료] 버튼 | — | — | → `POST /sessions/{id}/end` | 요청 |

**`context` jsonb 내용은 도메인마다 다르다** — 세일즈 `{nda_signed, stage}` / 채용 `{interview_round, position_level}`.
컬럼으로 박으면 도메인 추가 시 마이그레이션 발생 → 검증 조건 위배.

## ② 판정 카드 — 핵심 구역

| 화면 요소 | 필드 | 타입 | 출처 | 시점 |

| 정규화 질문 | `normalized_text` | text | `question.normalized_text` | 푸시 |
| 의도 배지 | `intent` | enum(exists/when/price/how/status) | `question.intent` | 푸시 |
| **할 말 문구** | `suggested_script` | text | `response_rule.suggested_script` | 푸시 |
| 조건 경고 | `condition` | text | `response_rule.condition` | 푸시 |

### ②-1 근거 펼침 (지연 로딩)

| 화면 요소 | 필드 | 타입 | 출처 |
|---|---|---|---|
| 근거 제목 | `heading_path` | string | `knowledge_chunk.heading_path` |
| 발췌 | `content` | text | `knowledge_chunk.content` |

> **처음부터 안 내려주고 클릭 시 가져온다.** 1.5초 예산에서 판정 카드가 우선이고,
> 근거는 사용자가 볼 때만 필요하다. 그래서 `GET /questions/{id}/evidence` API가 별도로 존재한다.

# 화면 2. 지식 공백 큐

담당 액터: 정보 승인자 (B1~B10)

```
┌─ ① 필터 ────────┬─ ③ 상세 ────────────────┐
│ 사유 ▾ 도메인 ▾  │ Edge Functions 셀프호스팅 │
│ 기간 ▾  [검색]   │ 지원 시점                │
├─ ② 큐 리스트 ────┤ 발생 5회 · 최초 09-02    │
│ ● Edge Fn 일정 5 │ intent: when             │
│ ● SOC2 갱신    3 │ ─ 원문 발화 ─            │
│ ○ 가격 티어    2 │ "그거 언제 되나요?"       │
│                 │ ─ 관련 GitHub 근거 ─      │
│                 │ #4821 (open) milestone…  │
│                 ├─ ④ 규칙 작성 폼 ─────────┤
│                 │ 모드 ▾ 등급 ▾ 조건 …      │
│                 │ [저장하고 해소] [기각]    │
└─────────────────┴──────────────────────────┘
```

## ① 필터

| 화면 요소 | 필드 | 타입 | 출처 | 시점 |

| 사유 선택 | `reason` | enum | `knowledge_gap.reason` | 요청 |

## ③ 상세 패널

| 화면 요소 | 필드 | 타입 | 출처 | 시점 |

| 정규화 질문 | `question_normalized` | text | `knowledge_gap.question_normalized` | 요청 |

### 저장 시 생성되는 것 (양방향 FK)

```
response_rule.created_from  →  knowledge_gap.id
knowledge_gap.resolved_by   →  response_rule.id
knowledge_gap.status        =  'resolved'
```

**이 양방향 연결이 "쓸수록 좋아진다"의 데이터 증거다.**

# 도출되는 API 목록

화면·시점 표에서 기계적으로 나온 것. **이 목록이 YML 명세의 뼈대다.**

| 리소스 | 메서드 · 경로 | 어느 화면·구역 |
|---|---|---|
| sessions | `POST /sessions` | 1-① 세션 시작 |
| | `GET /sessions/{id}` | 1-① 초기 로드 |
| | `PATCH /sessions/{id}/context` | 1-① 컨텍스트 수정 |
| | `POST /sessions/{id}/end` | 1-① 종료 |
| utterances | `GET /sessions/{id}/utterances` | 1-④ 히스토리 |
| | `WS /sessions/{id}/stream` | 1-②③④ 실시간 푸시 |
| questions | `GET /sessions/{id}/questions` | 1-③ |
| | `GET /questions/{id}` | 1-③ 항목 클릭 |
| | **`GET /questions/{id}/evidence`** | **1-②-1 근거 펼침** |
| | `POST /questions/{id}/reject` | 1-② 답변 틀림 |
| deferrals | `GET /deferrals` | 2-② 큐 리스트 |
| | `GET /deferrals/{id}` | 2-③ 상세 |
| | **`POST /deferrals/{id}/resolve`** | **2-④ 저장하고 해소** |
| | `POST /deferrals/{id}/reject` | 2-④ 기각 |
| policy-rules | `GET /policy-rules` | 3-③ 리스트 |

# 정합성 규칙 (D2 작업 시 준수)

1. 이 문서에 없는 필드는 ERD·API에 넣지 않는다
2. 이 문서에 있는 필드는 ERD·API에 반드시 넣는다
3. `시점` 열이 `요청`이면 대응 API 엔드포인트가 존재해야 한다
4. `출처`가 `계산`이면 ERD 컬럼이 아니라 API 응답 필드다
5. 예외 상태의 오류 코드(400/401/404/409)는 API 명세에 정의한다
