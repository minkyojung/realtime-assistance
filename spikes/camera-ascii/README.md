# camera-ascii

맥북 카메라를 켜서, 보이는 화면을 실시간으로 터미널에 ASCII 로 그린다.

```
make        # 빌드
make run    # 실행 (Ctrl-C 로 종료)
make test   # 카메라 없이 렌더링 파이프라인 검증
```

옵션은 `--mono` 하나. 기본은 트루컬러다.

## 왜 Swift 인가

Go 에서 macOS 카메라를 열려면 cgo 나 ffmpeg 파이프 같은 외부 의존성이 붙는다.
AVFoundation 을 직접 쓰는 단일 실행 파일이 의존성 없이 프레임 버퍼를 바로 읽을 수 있어서
이 스파이크는 Swift 로 갔다. 빌드에 필요한 건 Xcode CLT 의 `swiftc` 뿐이다.

## 구조

- `render.swift` — 순수 렌더링. BGRA 프레임 하나 → 터미널 한 화면 분량의 문자열.
- `main.swift` — AVFoundation 캡처 세션, 터미널 진입/복구, 시그널 처리.
- `rendertest/main.swift` — `render.swift` 만 링크해서 합성 그라데이션으로 검증한다.

렌더링을 캡처에서 떼어놨기 때문에 카메라 권한 없이도 테스트가 돈다.

## 어떻게 그리는가

1. `AVCaptureVideoDataOutput` 에서 32BGRA 프레임을 받는다 (VGA 640x480).
2. 출력 격자 크기를 정한다. 터미널 문자 칸이 대략 세로:가로 = 2:1 이라
   가로 칸 수를 두 배로 잡아야 화면 비율이 맞는다. 남는 공간은 가운데 정렬.
3. 각 칸에 대응하는 원본 픽셀 블록을 평균낸다 (단순 최근접 샘플링보다 노이즈가 적다).
4. 휘도(`0.299R + 0.587G + 0.114B`)를 램프 `" .:-=+*#%@"` 에 매핑한다.
5. 컬러 모드면 트루컬러 전경색을 얹는다. 인접 칸 색이 실질적으로 같으면
   이스케이프를 생략해서 프레임당 바이트 수를 줄인다.
6. 대체 화면 버퍼에 커서를 홈으로 되돌려 덮어쓴다. 줄 끝은 `ESC[K` 로 지운다.

좌우는 뒤집어서 그린다 — 셀카처럼 보이는 쪽이 자연스럽다.

## 카메라 권한

TCC 특성상 권한은 이 바이너리가 아니라 **이걸 실행한 터미널 앱**에 붙는다.
처음 실행하면 터미널 앱 이름으로 권한 요청이 뜬다. 거부했다면
시스템 설정 > 개인정보 보호 및 보안 > 카메라 에서 해당 터미널 앱을 켜고 다시 실행한다.

권한이 없으면 대체 화면에 들어가기 전에 메시지를 남기고 종료하므로 터미널이 깨지지 않는다.
