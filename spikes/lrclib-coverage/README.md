# LRCLIB 커버리지 스파이크

가사를 화면에 붙이기 전에 물어야 할 것은 하나다 —
**내 라이브러리의 몇 퍼센트에 가사가 있는가.**

## 왜 LRCLIB 인가

애플에서는 못 가져온다.

| 시도 | 결과 |
|---|---|
| Apple Music API `/songs/{id}/lyrics` | Music User Token + 애플 자체 앱 권한. 서드파티는 403 |
| AppleScript `lyrics of current track` | 파일에 직접 박아둔 가사만. **스트리밍 곡은 빈 값** |
| [LRCLIB](https://lrclib.net) | 무료 · 키 없음 · **타임스탬프 붙은 LRC** |

## 실행

```
cd spikes/lrclib-coverage
go run .           # 라이브러리 전체
go run . -limit 20 # 앞 20곡만
```

`~/Library/Caches/amcli/library.json` 을 읽는다. tui 를 한 번 띄워야 생긴다.

## 매칭 3단계

곡 하나에 최대 세 번 묻는다. 뒤로 갈수록 느슨하다.

1. `/api/get` — 제목·아티스트·앨범·길이가 전부 맞는 것
2. `/api/search` — 제목 + 아티스트
3. 제목을 깎아서 다시 검색 — `(Live at ...)` · `(feat. ...)` 같은 꼬리와,
   아티스트가 통째로 비어 제목 끝에 들어간 경우(`제목 - Jack Johnson`)

3단계가 커버리지를 4%p 올렸다. **라이브러리 메타데이터가 지저분한 것이지
가사가 없는 것이 아니다.**

## 실측 (2026-09-09 · 202곡)

| | 곡 | 비율 |
|---|---|---|
| **싱크 가사** — 재생 위치 따라 하이라이트 된다 | 137 | **67.8%** |
| 글자만 — 보여줄 수는 있으나 하이라이트 불가 | 47 | 23.3% |
| 연주곡 | 1 | 0.5% |
| 없음 | 17 | 8.4% |

없음 17곡 중 5곡은 애초에 음악이 아니다(오디오북 · Swift 문서 · Steve Jobs
연설). 그것을 빼면 **음악 197곡 중 하나도 못 찾은 것은 12곡, 6%.**

한글 곡은 2곡뿐이라 표본이 안 된다. 다만 둘 다 싱크 가사가 있었다.

소요 19~21초 (동시 4갈래). 남의 무료 서버이므로 그 이상 늘리지 않는다.

## 판정

```
하이라이트까지 되는 곡      약 70%
무엇이든 보여줄 수 있는 곡   약 93%
화면이 비는 곡              약  6%
```

**만든다.** 다만 30%는 하이라이트가 안 되고 6%는 아무것도 없으므로,
**없을 때의 화면을 먼저 정해야 한다.** 그것이 이 스파이크의 결론이다.
